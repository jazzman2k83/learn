SOME/IP in AUTOSAR Classic

SOME/IP

IDs, types and codes

The fixed values of SOME/IP and SOME/IP-SD in one place, for reading traces and configurations.

Message Type

The Message Type field of the SOME/IP header.

ValueNameUse
0x00REQUESTmethod call that expects a response, even an empty one
0x01REQUEST_NO_RETURNfire&forget method call
0x02NOTIFICATIONevent or field notifier; also every SOME/IP-SD message
0x80RESPONSEresponse to a REQUEST, Return Code E_OK
0x81ERRORresponse to a REQUEST that failed; the Return Code says why (the Classic Platform SOME/IP transformer sends it without exception data)
0x20 0x21 0x22 0xA0 0xA1TP_REQUEST … TP_ERRORthe same Message Types for a segment of SOME/IP TP: TP flag 0x20 added

Return Code

The Return Code field of the SOME/IP header.

ValueNameMeans
0x00E_OKno error; the only value allowed in a REQUEST or NOTIFICATION
0x01E_NOT_OKunspecified error
0x02E_UNKNOWN_SERVICEService ID unknown
0x03E_UNKNOWN_METHODMethod ID unknown, service known
0x04E_NOT_READYservice and method known, application not running
0x05E_NOT_REACHABLEused only inside the client, never sent
0x06E_TIMEOUTused only inside the client, never sent
0x07E_WRONG_PROTOCOL_VERSIONProtocol Version not supported
0x08E_WRONG_INTERFACE_VERSIONInterface Version does not match
0x09E_MALFORMED_MESSAGEpayload cannot be deserialized
0x0AE_WRONG_MESSAGE_TYPEunexpected Message Type
0x0B–0x0FE2E return codes (PRS)repeated, wrong sequence, generic, not available, no new data; the Classic Platform transformer table lists only 0x0B E_E2E
0x10–0x1Freservedfuture generic SOME/IP errors
0x20–0x5Eservice specificin the Classic Platform: the ApplicationError of the ClientServerOperation + 0x1F

SOME/IP TP

SOME/IP TP header4 bytes after the 16-byte SOME/IP header: Offset (upper 28 bits, unit 16 bytes), 3 reserved bits, More Segments flag
Segment sizemultiple of 16 bytes except the last; at most 1392 bytes of payload for UDP
UDP payload limit1400 bytes of SOME/IP payload without segmentation
