SOME/IP

The SD message, byte by byte

A SOME/IP-SD message is a SOME/IP NOTIFICATION with a fixed SOME/IP header, a Flags byte, an array of 16-byte entries and an array of options.

The frame of every SD message

Bit of the Flags byteNameValue sent
0x80 (highest)Reboot flag1 after a reboot until the Session ID wraps (lesson 16)
0x40Unicast flagalways 1: "I can receive unicast SOME/IP-SD messages"; kept for compatibility
0x20Explicit Initial Data Control flagalways 1: "I honour the Initial Data Requested flag"
othersundefined0 when sending, ignored when receiving

Entries

Every entry is 16 bytes long and comes in one of two formats: a service entry (Type 1 format, for FindService and OfferService) or an eventgroup entry (Type 2 format, for SubscribeEventgroup and SubscribeEventgroupAck). Each entry points to its options through two option runs (a start index into the options array plus a number of options).

Specification note: the R20-11 Service Discovery module specification still draws the 12 bits before the Counter as reserved and does not mention the Initial Data Requested flag or the Explicit Initial Data Control flag; the R20-11 protocol specification defines both. The course follows the protocol specification.

Options

Every option starts with a 2-byte Length (counting everything after the Type byte, so the reserved byte too), a 1-byte Type, and a byte whose top bit is the Discardable flag (set if a receiver that does not know this option may ignore it).

TypeOptionLengthContent after the 4-byte start
0x01Configuration optionvariablename=value strings, each behind a 1-byte length, ending with a zero byte
0x02Load Balancing option0x0005priority (2 bytes, lower = preferred), weight (2 bytes)
0x04IPv4 Endpoint option0x0009IPv4 address (4), reserved (1), protocol (1: 0x06 TCP, 0x11 UDP), port (2)
0x06IPv6 Endpoint option0x0015IPv6 address (16), reserved, protocol, port
0x14IPv4 Multicast option0x0009multicast address, reserved, protocol 0x11 (UDP only), port
0x16IPv6 Multicast option0x0015as above, 16-byte address
0x24IPv4 SD Endpoint option0x0009the sender's Sd address and port; first option, never referenced by an entry
0x26IPv6 SD Endpoint option0x0015as above for IPv6

The SOME/IP-SD port is 30490 (0x771A) by default. An OfferService references one Endpoint option per transport protocol it serves; a SubscribeEventgroup references the client's Endpoint options; a SubscribeEventgroupAck references at most one Multicast option; a FindService references no Endpoint options.

Specification note: one passage of the R20-11 protocol specification gives 0x0015 as length of the IPv4 SD Endpoint option; its figure and the module specification give 0x0009, which matches the 9 bytes that follow.

Try it

Build a SOME/IP-SD message, or paste one and decode it. The preset "Example from the specification" is the example PDU of the protocol specification (a FindService and an OfferService for a non-SOME/IP service).

    Things to notice. A StopOfferService differs from the OfferService only in the three TTL bytes. A SubscribeEventgroupNack differs from the Ack only in its TTL and the missing options. In the OfferService, the single entry points to options 0 and 1 with Index 1st options 0 and # of opt 1 = 2. Decode the specification's example: its Configuration option carries "otherserv=internaldiag" behind the length byte 0x16 (22).
