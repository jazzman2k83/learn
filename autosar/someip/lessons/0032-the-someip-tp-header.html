SOME/IP in AUTOSAR Classic

SOME/IP

The SOME/IP TP header

Every segment of a segmented message carries the normal 16-byte SOME/IP header plus the 4-byte SOME/IP TP header: the Offset where the segment starts in the original payload, counted in units of 16 bytes, and the More Segments flag, which says whether more segments follow.

Twenty bytes in front of each segment

A segment repeats the SOME/IP header of the original message with two changes, the Length and the TP flag in the Message Type, and adds the SOME/IP TP header right after it.

Offset

Units of 16 bytes

The 32-bit word holds the byte offset with its lowest 4 bits used for flags, so offsets are always multiples of 16. Offset value 87 means byte 87 × 16 = 1392 of the original payload.

size

At most 1392 bytes

A UDP SOME/IP payload is limited to 1400 bytes; minus the 4-byte SOME/IP TP header that leaves 1396, and the largest multiple of 16 below is 1392. Every segment except the last is a multiple of 16; all those segments are equally long.

same values

One Session ID

Session handling is on for segmented messages, and all segments of one original message carry its Session ID, Message ID, versions and Return Code. The receiver uses them to know which segments belong together.

What the AUTOSAR module checks

The SOME/IP TP module of the Classic Platform is deliberately simple: it does not put segments back in order and does not ask for repeats. On reception it stops the current reassembly when a segment's Offset does not match the bytes received so far, when the header values differ from the first segment, when a segment with the More Segments flag 1 is not a multiple of 16 bytes, or when its receive timeout runs out. A segment with an Offset greater than 0 and no reassembly running is ignored. The upper layer (PduR) is told about the first segment with an unknown total length and gets the rest segment by segment.
