SOME/IP in AUTOSAR Classic

SOME/IP

What SOME/IP is for

SOME/IP lets one ECU offer a service over Ethernet and lets other ECUs use it: receive its events, call its methods, read and change its fields.

SOME/IP (Scalable service-Oriented MiddlewarE over IP: the protocol that lets ECUs offer and use services over Ethernet) is the AUTOSAR way to exchange application data between ECUs on Ethernet. This lesson shows what it changes compared with classic CAN signals.

Two ways to share data

On CAN, a sender puts its signals into frames and sends them on a fixed schedule. Every ECU on the bus sees every frame, and each one decides for itself what to keep. The sender does not know who is listening.

Service-oriented communication (communication organised around services instead of fixed signals on a fixed schedule) turns this around. A server (the ECU that provides a service) says "I offer this service". A client (an ECU that uses the service) asks for exactly the parts it needs. An event (a message the server sends on its own when something happens or a value changes) goes only to the clients that subscribed to it, and a client can call a method (a function of the server) and get a response back.

Fewer useless messages matter on Ethernet, where one ECU may serve many others and the data can be large: camera frames, object lists, maps. Service-oriented communication also adds something CAN signals cannot do at all: a method call with a response (a remote procedure call).

What SOME/IP brings

on every message

SOME/IP header

The SOME/IP header (a short block in front of the data of every message) says which service, which method or event, what kind of message, and which call it belongs to.

for the data

Serialization

Serialization (writing the data out as a row of bytes in a fixed order) turns numbers, structures, arrays and strings into the same bytes on every ECU.

server to clients

Events

The server sends an event to every client that subscribed to it.

client to server

Methods

A client calls a method of the server, with or without a response.

a separate protocol

Service Discovery

SOME/IP-SD (SOME/IP Service Discovery: the messages with which servers offer their services and clients find them and subscribe) runs beside the data messages.

Where it sits

SOME/IP is not a new kind of network. Its messages travel inside ordinary internet protocols: UDP or TCP, on IP, on Ethernet. A service can use UDP (fast and lean, a lost datagram is not repeated) for small, frequent messages and TCP (lost data is repeated and order is kept) where nothing may be lost.

The name says the same thing: Scalable service-Oriented MiddlewarE over IP. The only correct short form is SOME/IP.

Things to notice. With signal-based communication every frame reaches every ECU on the bus, needed or not. With service-oriented communication an event reaches only the clients that subscribed to it, and an ECU that does not need the data never sees it. The method call with a response is new: CAN signals have nothing like it.
