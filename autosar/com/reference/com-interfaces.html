RTE and the other COM users

The RTE is COM's main user. In a system built from software clusters, SwCluC takes this role for the clusters (both are a COM user). The application SWCs never call COM themselves.

FunctionDirectionWhat forLesson
Com_SendSignal, Com_ReceiveSignalRTE → COMWrite a signal for transmission; read the current value of a received signal.9
Com_SendSignalGroup, Com_ReceiveSignalGroupRTE → COMCopy a signal group between its shadow buffer and the I-PDU. The group signals themselves go through Com_SendSignal / Com_ReceiveSignal.10
Com_SendSignalGroupArray, Com_ReceiveSignalGroupArrayRTE → COMThe same for a whole signal group as one byte array, without a shadow buffer.10
Com_SendDynSignal, Com_ReceiveDynSignalRTE → COMWrite or read a dynamic length signal together with its length.13
Com_InvalidateSignal, Com_InvalidateSignalGroupRTE → COMWrite the data invalid value.7
Com_TransmitRTE → COMTransmit an I-PDU on the Large Data Path.13
Com_Send…WithMetaData, Com_Receive…WithMetaDataRTE → COMVariants of all the above that also pass the meta data of the I-PDU (for example a CAN identifier).–
Com_TriggerIPDUSend (and …WithMetaData)COM user or BswM → COMSend a whole I-PDU once, now.–
Rte_COMCbk_<sn>COM → RTEComNotification on reception: the signal (or signal group) arrived and passed all checks.9
Rte_COMCbkTAck_<sn>COM → RTEComNotification on transmission: the I-PDU was confirmed.9
Rte_COMCbkTErr_<sn>COM → RTEComErrorNotification: the I-PDU was stopped before it was confirmed.9, 11
Rte_COMCbkInv_<sn>COM → RTEComInvalidNotification: the data invalid value arrived.7, 9
Rte_COMCbkRxTOut_<sn>, Rte_COMCbkTxTOut_<sn>COM → RTEComTimeoutNotification of reception or transmission deadline monitoring.6, 9
Rte_COMCbkTxConfirmation, …RxIndication, …TriggerTransmit, …CopyTxData, …StartOfReception, …CopyRxData, …TpRxIndication, …TpTxConfirmationCOM → RTELarge Data Path only: COM passes the PduR's calls for this I-PDU straight on to the RTE.13

<sn> is the name of the signal or signal group. The specification writes the callbacks neutrally, for any COM user: <ComUser_CbkRxAck>, <ComUser_CbkTxAck>, <ComUser_CbkTxErr>, <ComUser_CbkInv>, <ComUser_CbkRxTOut>, <ComUser_CbkTxTOut> and <ComUser_ComCbk…> for the Large Data Path. Their names are configured in ComUserCallback.

PduR

The only module below COM. COM uses both kinds of PduR interface: the one for interface modules (CanIf, SoAd, …) and the one for transport protocols (CanTp, …).

FunctionDirectionWhat forLesson
PduR_ComTransmitCOM → PduRTransmit this I-PDU. The only mandatory interface of COM.14
PduR_ComCancelTransmitCOM → PduRCancel an ongoing transmission (only with ComIPduCancellationSupport).–
Com_RxIndicationPduR → COMAn I-PDU has arrived.14
Com_TxConfirmationPduR → COMAn I-PDU was transmitted (or not: result E_NOT_OK).14
Com_TriggerTransmitPduR → COMGive me the current content of this I-PDU, now.14
Com_CopyTxData, Com_TpTxConfirmationPduR → COMTransmission of a large I-PDU: copy the next bytes; the whole I-PDU was sent.13, 18
Com_StartOfReception, Com_CopyRxData, Com_TpRxIndicationPduR → COMReception of a large I-PDU: one is coming, with this length; here are the next bytes; it is complete.13, 18

BswM

The BswM switches COM on and off and decides which I-PDUs run, depending on the mode of the ECU and its networks. The BSW Mode Manager specification lists these functions as the ones it may call; in a project they are configured as BswM actions.

FunctionDirectionWhat forLesson
Com_InitBswM → COMInitialise COM at start-up. All I-PDU groups are still stopped afterwards.11
Com_DeInitBswM (or EcuM) → COMStop COM: all I-PDU groups are stopped and COM is no longer initialised.–
Com_IpduGroupStart, Com_IpduGroupStopBswM → COMStart or stop all I-PDUs of an I-PDU group.11
Com_EnableReceptionDM, Com_DisableReceptionDMBswM → COMSwitch reception deadline monitoring on or off for an I-PDU group.6, 11
Com_SwitchIpduTxModeBswM → COMSelect the true or false transmission mode of an I-PDU from outside.4
Com_TriggerIPDUSendBswM → COMSend an I-PDU once, now, as a configured BswM action.–

Older 4.x releases controlled I-PDU groups with a group vector instead: Com_IpduGroupControl and Com_ReceptionDMControl. You may still see them in existing code.

BSW Scheduler

The BSW Scheduler (SchM, part of the RTE) calls COM's main functions from OS tasks, at the period configured for each one. Several instances of each are possible; each gets the short name of its configuration container added, for example Com_MainFunctionTx_Fast.

FunctionDirectionWhat forLesson
Com_MainFunctionTxSchM → COMPeriodic transmissions, repetitions, minimum delay time, transmission deadline monitoring, deferred transmission notifications.2, 3, 6
Com_MainFunctionRxSchM → COMDeferred processing of received I-PDUs (DEFERRED), reception deadline monitoring.2, 6
Com_MainFunctionRouteSignalsSchM → COMThe signal gateway. Its period sets the latency of the gateway.12

I-PDU callouts

An I-PDU callout is a function written for the project, not a module. COM calls it for one I-PDU, under the name given in the configuration (ComIPduCallout, ComIPduTriggerTransmitCallout).

FunctionDirectionWhat forLesson
Rx I-PDU calloutCOM → project codeCalled for a received I-PDU before COM unpacks it. Returns false: COM drops the I-PDU (for example as a filter of your own).–
Tx I-PDU calloutCOM → project codeCalled before an I-PDU is handed to the PduR, for example to fill in a counter or a checksum. Returns false: COM does not transmit it.–
Trigger transmit calloutCOM → project codeThe same, inside Com_TriggerTransmit.–

Below the PduR

COM never calls CanIf, CanTp, SoAd, IpduM, SecOC or a driver, and none of them calls COM. Everything goes through the PduR, which uses the same COM functions whatever sits below it. That is why COM works the same on every bus. Lesson 14 shows the layers; lesson 18 shows the full call chains for CAN, CanTp and Ethernet.

Source: AUTOSAR COM specification, R25-11: chapter 5 (dependencies, Figure 5.1 context view), sections 8.3 to 8.6 (provided, scheduled, expected and configurable interfaces, Tables 7.6 and 8.1), 7.11 (Det and Dem); BSW Mode Manager, R25-11, SWS_BswM_00008; RTE, R25-11, for the Rte_COMCbk… names. Com_DeInit has no fixed caller in the specifications; BswM or EcuM is the usual choice.
