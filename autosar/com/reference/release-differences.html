Differences between releases

The course follows release R25-11. Many ECUs still run on 4.4.0 or R20-11. What COM does is the same in all three; some of the configuration and a few functions around it differ. This sheet lists those differences.

The same in 4.4.0, R20-11 and R25-11

Every feature of lessons 1 to 12 and 16 to 17 works the same in all three releases, with the same names and the same values: transfer property, transmission mode and transmission mode selection, repetitions and minimum delay time, init values and update-bits, deadline monitoring with NONE, REPLACE and SUBSTITUTE, data invalid values, the eight filter algorithms, IMMEDIATE and DEFERRED, signal groups, I-PDU groups with Com_IpduGroupStart and Com_IpduGroupStop, the signal gateway, large I-PDUs and dynamic length signals, signal types and byte order. The functions the RTE and the PduR call are the same too, except Com_Transmit (below).

I-PDU counter and I-PDU replicationPresent: a sequence counter inside the I-PDU that the receiver checks (ComIPduCounter), and a received I-PDU that arrives up to three times, with COM comparing the copies and passing the signals on only if enough of them are identical (ComIPduReplication).Removed in R21-11.–

Meta data in the signal functionsOnly Com_TriggerIPDUSendWithMetaData.Also Com_SendSignalWithMetaData, Com_ReceiveSignalWithMetaData and the same for signal groups and dynamic length signals. Added in R19-11.–
Security eventsNo.COM can report a security event when a filter drops a received signal (filters other than ONE_EVERY_N and NEVER). Added in R24-11.–
Software clustersNo. The RTE is the only COM user.SwCluC can be a COM user too. Added in R21-11.–

Two smaller points. Some rules were only written down more precisely in later releases, without a change in behaviour: for example that reception deadline monitoring starts again after a timeout, so the timeout notification repeats. And in R25-11, many configuration rules got their own IDs (SWS_Com_CONSTR_…); their content is unchanged.
