AUTOSAR COM

Signal groups

Some values only make sense together, like the x and y of a position. A signal group makes sure they always travel as a matching set.

The problem

An application writes x, then y. These are two separate steps. If the packet happens to go out between them, it carries the new x with the old y. The receiver gets a position that never existed.

The fix: a staging area

Put x and y into a signal group. Now writing x or y does not touch the packet. The values go into a staging area first. When all of them are written, the application says "hand over the group", and COM copies the whole set into the packet in one uninterruptible step.

Receiving works the same way in reverse: "fetch the group" copies the whole set from the packet into the staging area in one step, and the application then reads x and y from there.

What belongs to the group, what to its members

The group is treated as one thing. So most extras from the earlier lessons are set once for the whole group, not per member.

FeatureSet for
Update-bitThe whole group
Messages to the application, timeoutsThe whole group
Triggered or pendingThe whole group, or finer per member
Filter, send-setting conditionEach member

All or nothing also holds on the receiving side: if a filter blocks one member, the whole group is dropped. If one member carries the "invalid" value, the whole group is treated as invalid.
