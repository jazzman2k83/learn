Signal groups

Some values only make sense together, like the x and y of a position. A signal group makes sure they always travel as a matching set.

The problem

The SWC writes x, then y. The RTE makes two separate calls of Com_SendSignal. If the I-PDU happens to go out between them, it carries the new x with the old y. The receiver gets a position that never existed.

The fix: a shadow buffer

Put x and y into a signal group (a set of signals that COM sends and receives consistently, as one matching set). Each of them is now a group signal (one signal inside a signal group). Writing x or y no longer touches the I-PDU. The values go into a shadow buffer first (a copy of the signal group where its group signals are collected). When all of them are written, the RTE calls Com_SendSignalGroup (the COM API that copies the shadow buffer into the I-PDU), and COM copies the whole set in one uninterruptible step.

RTECom_SendSignal for x and for y, then Com_SendSignalGroup
→
Shadow bufferholds the set while it is being put together
→
I-PDUonly ever holds complete sets

Reception works the same way in reverse: Com_ReceiveSignalGroup (the COM API that copies the signal group from the I-PDU into the shadow buffer) copies the whole set in one step, and the RTE then reads x and y from there with Com_ReceiveSignal.

Try it

Move the position from (1, 1) to (2, 2). Try to catch COM in between: write x, then let the I-PDU go out before writing y.

What belongs to the signal group, what to its group signals

The signal group is treated as one thing. So most features from the earlier lessons are set once for the whole signal group, not per group signal.

FeatureSet for
Update-bitThe whole signal group
Notifications, deadline monitoringThe whole signal group
Transfer propertyThe whole signal group, or finer per group signal
Filter, transmission mode conditionEach group signal

All or nothing also holds in reception: if a filter blocks one group signal, the whole signal group is dropped. If one group signal carries its data invalid value, the whole signal group is treated as invalid.

TermMeaning
signal groupA set of signals that COM sends and receives consistently, as one matching set.
group signalOne signal inside a signal group.
shadow bufferA copy of the signal group where its group signals are collected or read, so the I-PDU always holds a consistent set.
Com_SendSignalGroupCopies the shadow buffer into the I-PDU in one step.

Source: AUTOSAR COM specification, R25-11, section 7.3 (SWS_Com_00050, 00051, Table 7.5, SWS_Com_00836, 00682). Finer point: there is a second way without a shadow buffer. The RTE hands COM the whole signal group as one ready-made block of bytes (Com_SendSignalGroupArray, Com_ReceiveSignalGroupArray). It is used when the data was already serialized by another part of the software.
