AUTOSAR COM

Notifications

When something happens to a signal, COM can call a function of the RTE to say so. Such a call is a notification. A signal can have up to six of them. This lesson also puts the reception steps of lessons 5 to 8 in order.

Two ways to stay informed

An SWC never calls COM itself. The RTE does it for the SWC: it writes a signal with Com_SendSignal (the COM API that writes a signal value for transmission) and reads one with Com_ReceiveSignal (the COM API that returns the current value of a received signal).

Ask

The SWC reads the signal whenever it likes and gets the current value through Com_ReceiveSignal. Simple, but it does not know when something changed.

Be told

COM calls a notification (a callback function of the RTE) at the moment something happens. Each kind is configured per signal or signal group.

The six notifications

The specification knows four kinds of notification. Two of them exist on both sides, which makes six. For each one the RTE provides its own callback.

SideNotificationCallback in the RTEWhen
ReceptionComNotificationRte_COMCbkA signal arrived and passed all checks.
ReceptionComTimeoutNotificationRte_COMCbkRxTOutThe timeout of reception deadline monitoring ran out (lesson 6).
ReceptionComInvalidNotificationRte_COMCbkInvThe data invalid value arrived and the ComDataInvalidAction is NOTIFY (lesson 7).
TransmissionComNotificationRte_COMCbkTAckThe lower layers confirmed the transmission of the I-PDU. With repetitions: after the last one.
TransmissionComTimeoutNotificationRte_COMCbkTxTOutTransmission deadline monitoring: no confirmation within the timeout (lesson 6).
TransmissionComErrorNotificationRte_COMCbkTErrThe I-PDU was stopped while a transmission was still not confirmed (lesson 11).

The RTE generates one such callback per signal, with the signal's name added, for example Rte_COMCbk_Speed. Remember IMMEDIATE and DEFERRED from lesson 2? This signal processing setting of the I-PDU decides when these calls are made: in the moment itself, or in COM's next main function.

The reception steps, in order

When an I-PDU arrives, each signal in it goes through the same fixed line of steps. A signal can drop out along the way. Pick a situation and see how far it gets.

    The order explains some behaviour you might otherwise find odd. The reception deadline monitoring timer of the I-PDU is reset first, so even an I-PDU whose signals are all dropped still counts as "the sender is alive". And the filter comes after the check for the data invalid value, so with NOTIFY an invalid value never reaches the filter.
