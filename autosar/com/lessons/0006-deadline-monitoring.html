AUTOSAR COM

Deadline monitoring

Silence can be dangerous. If the brake ECU stops sending, the others must find out. COM checks that signals arrive in time, and that its own transmissions are confirmed in time.

Reception deadline monitoring

For a signal that should arrive regularly, COM can run deadline monitoring (COM checking that something happens within a set time). On the receiving side this is reception deadline monitoring (detecting that a received signal did not arrive within its time). The time allowed is the timeout (the time after which a missing reception or confirmation is reported). COM starts a timer, and each reception of the I-PDU restarts it. If the timer reaches the timeout, COM does two things:

1. Decide the signal value

Chosen per signal: NONE (keep the last received value), REPLACE (go back to the init value) or SUBSTITUTE (use the timeout substitution value, a value configured for this case).

2. Notify the RTE

COM calls a timeout notification (a function of the RTE that COM calls when something happens to a signal; lesson 9), so the SWC can react, for example by showing a warning.

Then the timer starts again. As long as nothing arrives, COM calls the timeout notification again each time the timeout passes.

Try it

The timeout is 3 seconds. Let I-PDUs arrive, then stop clicking and watch. The init value is 0 and the timeout substitution value is 99.

One timer or several?

Normally COM monitors the whole I-PDU with one timer: if the I-PDU arrives, all its signals are fine. A signal with an update-bit gets its own timer, because the I-PDU may arrive without that signal being new.

The very first reception after start-up can have its own, usually longer, time: the first timeout (the timeout used for the first reception after the I-PDU was started). Other ECUs may need time to start up.

Transmission deadline monitoring

COM can also monitor its own transmissions. This is transmission deadline monitoring (detecting that the lower layers did not confirm a transmission within its timeout). When COM hands an I-PDU to the PduR, it expects the transmit confirmation (the report from the lower layers that the I-PDU was sent on the bus) within the timeout. If the confirmation does not come, for example because the wire is broken, COM notifies the RTE.

One difference: this timeout notification comes once per failed transmission. The timer is not restarted.

Source: AUTOSAR COM specification, R25-11, section 7.2.6 (SWS_Com_00290, 00292, 00470, 00875, 00500, 00889, 00878, 00304). Finer points: a timeout of 0 switches deadline monitoring off. COM can also report timeouts to the diagnostic event manager (Dem). Transmission deadline monitoring only makes sense on a bus that confirms transmissions. Reception deadline monitoring runs only while the I-PDU group of the I-PDU (a set of I-PDUs started and stopped together, lesson 11) has it enabled.
