AUTOSAR COM

Transfer property, transmission mode and signal processing

Three settings decide the timing in COM. The transfer property of a signal says whether writing it sends its I-PDU. The transmission mode of an I-PDU says when it is sent. The signal processing of an I-PDU says when a received one is handled. Try the two timelines below and you will know all three.

Two timing questions

From lesson 1: an SWC writes signals through the RTE, and COM carries them in I-PDUs. That leaves COM two timing questions: when does an I-PDU go out, and when does the receiver hear about one that arrived? Three settings answer them.

Sending: transfer property and transmission mode

The question: when the SWC writes a new value, does the I-PDU go out because of it? The first answer is a setting of each signal, its transfer property (whether writing the signal makes its I-PDU go out). It has two basic values, TRIGGERED and PENDING:

set per signal

TRIGGERED

"Send it now." Writing this signal makes the I-PDU go out.

set per signal

PENDING

"No rush." The new value waits in COM and goes out with the next transmission of the I-PDU, whatever causes it.

What else causes a transmission? A TRIGGERED signal in the same I-PDU, or a timer. Whether there is a timer is decided by the transmission mode of the I-PDU (when COM sends it). It has four values, DIRECT, PERIODIC, MIXED and NONE:

set per I-PDU

DIRECT

No timer. The I-PDU only goes out when a TRIGGERED signal is written.

set per I-PDU

PERIODIC

Timer only. The I-PDU goes out at a fixed period and nothing else.

set per I-PDU

MIXED

Both. Timer, plus right away when a TRIGGERED signal is written.

set per I-PDU

NONE

Neither. COM never starts a transmission of the I-PDU by itself.

Try it

One I-PDU carries two signals. Speed is TRIGGERED, Temp is PENDING. Write some values and watch the bus lane. A label like S2 T1 means the I-PDU carried Speed 2 and Temp 1. Then change the transmission mode and try again.

Things to notice. With DIRECT, a Temp you write stays in COM until you write a Speed. With PERIODIC, even writing Speed sends nothing until the timer fires. With MIXED you get both.

Receiving: signal processing

The question: when an I-PDU arrives, when does the RTE hear about it? The answer is the signal processing of the I-PDU (whether COM handles a received I-PDU at once or later). It has two values, IMMEDIATE and DEFERRED:

set per I-PDU

IMMEDIATE

Right now, in the same moment the I-PDU arrives.

set per I-PDU

DEFERRED

A little later. COM keeps the data and processes it, and notifies the RTE, the next time its main function runs.

That regular job is COM's main function (a function of COM that the scheduler calls at a fixed period). COM has one main function for reception and one for transmission. DEFERRED is calmer for the system, because the work is done in the main function and not at the moment of reception. IMMEDIATE is faster.

Try it

Let a few I-PDUs arrive and watch when the RTE is notified. The small dots are the calls of the main function.

What you can do now. Read these three settings in any COM configuration and say what will happen: does a write cause a transmission, and when does the receiver hear about it.

New terms in this lesson

TermMeaning
transfer propertySetting of a signal: whether writing it makes its I-PDU go out.
TRIGGEREDEvery write of the signal makes its I-PDU go out (when the transmission mode is DIRECT or MIXED).
PENDINGWriting the signal sends nothing; the new value goes out with the next transmission of its I-PDU.
transmission modeSetting of an I-PDU: when COM sends it.
DIRECTThe I-PDU is sent only when a TRIGGERED signal is written.
PERIODICThe I-PDU is sent at a fixed period; writes do not trigger a transmission.
MIXEDThe I-PDU is sent periodically and also when a TRIGGERED signal is written.
NONECOM never starts a transmission of the I-PDU by itself.
signal processingSetting of an I-PDU: whether a received I-PDU is processed and notified at once or in the next main function.
IMMEDIATECOM processes a received I-PDU and notifies the RTE right away.
DEFERREDCOM keeps a received I-PDU and processes and notifies it in its next main function.
main functionA function of COM that the scheduler calls at a fixed period; there is one for reception and one for transmission.

Source: AUTOSAR COM specification, R25-11, sections 7.2.3.1 and 7.2.5.4 (SWS_Com_00330, SWS_Com_00300, SWS_Com_00301). "Right away" for a TRIGGERED signal means at the latest when COM's main function next runs. TRIGGERED also has variants: only on a changed value, and with or without repetitions (see the next lesson).
