AUTOSAR COM

PduR and the lower layers

COM never touches the bus. It hands I-PDUs to one module below it, the PduR, and gets I-PDUs from it. Here is the whole way down and up again, for CAN and for Ethernet.

Layers, each with one job

The software in an ECU is built in layers. Each layer talks only to the one above and the one below. That is why COM can be the same on every bus: everything specific to a bus lives further down.

LayerIts one job
SWCThe actual function: compute, decide, display.
RTEConnects the SWCs with each other and with the basic software, COM included.
COMSignals into and out of I-PDUs, and when. This course.
PduRLooks up where each I-PDU goes. Never looks inside.
Bus-specific modulesTurn an I-PDU into what this bus needs, and drive the hardware.

For CAN the bus-specific modules are CanIf (CAN Interface: hands frames between the PduR and the CAN driver), CanTp (CAN Transport Layer: the transport protocol for large I-PDUs, lesson 13) and the CAN Driver (Can: drives the CAN hardware). What travels in one frame is an L-PDU (Data Link Layer PDU: the unit that CanIf hands to the driver). For Ethernet they are SoAd (Socket Adaptor: maps I-PDUs to UDP or TCP connections), TcpIp (the TCP/IP stack), EthIf (Ethernet Interface) and the Ethernet Driver (Eth: drives the Ethernet hardware).

The calls at the borders of COM

All traffic between COM and its neighbours goes through a few calls. In real COM code or a trace, these are the names you will see.

CallDirectionMeaning
Com_SendSignalRTE to COM"Here is a new value for this signal."
Com_ReceiveSignalRTE to COM"Give me the current value of this signal."
PduR_ComTransmitCOM to PduR"Transmit this I-PDU."
Com_TxConfirmationPduR to COM"Your I-PDU was transmitted."
Com_RxIndicationPduR to COM"An I-PDU arrived for you."
Com_TriggerTransmitPduR to COM"It is about to be sent. Give me the content of this I-PDU now."

A large I-PDU (lesson 13) uses a second set of calls via the transport protocol: Com_CopyTxData and Com_TpTxConfirmation for transmission, Com_StartOfReception, Com_CopyRxData and Com_TpRxIndication for reception.

Lesson 18, The whole call sequence, follows these calls through every layer, with the function names of CanIf, CanTp, SoAd and the drivers. The sheet COM's interfaces lists every function between COM and its neighbours.

Two notes on Ethernet

Same COM, other modules below

Below the PduR, SoAd turns "transmit this I-PDU" into "send these bytes over this socket connection". COM itself does not change.

Service data is often serialized above COM

On Ethernet, data is often turned into bytes above COM, by a transformer (a module that the RTE calls to serialize data into bytes, for example the SOME/IP transformer). COM then receives a finished block and passes it through, as on the Large Data Path of lesson 13.
