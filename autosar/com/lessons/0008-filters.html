AUTOSAR COM

Filters

Not every received value is interesting. A filter is a simple yes-or-no rule on a signal value: it lets the value through to the RTE, or drops it.

What a filter does

A filter (a rule on a signal value with the result pass or block) belongs to one received signal. Each time a value for that signal arrives, COM evaluates the filter: pass or block?

Pass

COM stores the value and notifies the RTE, as usual.

Block

COM discards the value. Nothing is stored, nobody is notified. A read still gives the previous value.

This saves the SWC work. An SWC that only cares about changes is not woken up for the same value again and again.

The eight filter algorithms

The rule itself is the filter algorithm. COM offers eight:

Filter algorithmThe value passes…
ALWAYSalways
NEVERnever
MASKED_NEW_DIFFERS_MASKED_OLDonly if it is different from the last value that passed
MASKED_NEW_EQUALS_Xonly if it equals a fixed value X
MASKED_NEW_DIFFERS_Xonly if it differs from a fixed value X
NEW_IS_WITHINonly if it is inside a range
NEW_IS_OUTSIDEonly if it is outside a range
ONE_EVERY_Nonly at every Nth arrival

"Masked" means the comparison can be limited to some of the value's bits, for example to ignore the lowest bits so that tiny changes do not count.

Try it

Pick a filter algorithm, set a value, and let it arrive. Here X is 50, the range is 20 to 60, and N is 3.

    Things to notice. With MASKED_NEW_DIFFERS_MASKED_OLD, receive the same value twice: the second is blocked. With ONE_EVERY_N, the first arrival passes, then two are blocked.

    Same filters, second use. On the sending side the same filter algorithms serve as the transmission mode conditions that feed the transmission mode selector (lesson 4). There they never drop anything.
