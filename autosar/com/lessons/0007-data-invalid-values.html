AUTOSAR COM

Data invalid values

Sometimes a sending ECU is alive but has nothing good to say: its sensor is broken. It needs a way to send "no valid value" in a signal.

One value means "invalid"

Staying silent would trigger reception deadline monitoring at the receiver, and a timeout means something else: "the sender is gone". So the configuration gives the signal a data invalid value (one configured value of the signal that means "no valid value available"). For a speed that normally runs from 0 to 250, the value 255 could be the data invalid value.

sender

Invalidate

The RTE calls Com_InvalidateSignal (the COM function that writes the data invalid value into a signal). COM writes the data invalid value into the I-PDU. It is transmitted like any other value.

receiver

Recognise

COM sees the data invalid value arrive and does one of two things, chosen per signal.

The receiver's two choices

The data invalid action (what the receiver does with a data invalid value) is one of two values:

choice 1

NOTIFY

With NOTIFY, COM calls the invalid notification (a function of the RTE that COM calls when something happens to a signal; lesson 9). It does not store the data invalid value: a read still gives the last valid value.

choice 2

REPLACE

With REPLACE, COM swaps the data invalid value for the signal's init value and carries on as if that had been received.

Try it

The data invalid value is 255 and the init value is 0.

Source: AUTOSAR COM specification, R25-11, section 7.2.4 (SWS_Com_00099, 00680, 00681, 00717). Finer points: a data invalid value still counts as a reception, so it restarts the reception deadline monitoring timer. With NOTIFY, a read before any valid value was received gives the init value.
