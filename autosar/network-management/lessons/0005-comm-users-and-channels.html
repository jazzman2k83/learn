Network and Mode Management in AUTOSAR Classic

Network Management

ComM users and channels

ComM does not know SWCs or functions. It knows users, each of which asks for full or no communication, and channels, one per network. The configuration maps each user to channels or to PNCs, and per channel the highest request wins.

Lesson 4 followed one request of UserComfort down to the bus. This lesson looks at the requests themselves: who may make them, what they can ask for, and how ComM combines them.

Users and channels

who asks

ComM user

A ComM user (a logical requester of communication in ComM; an SWC, a function of it or a BSW module) is a configured entry with a handle. It is mapped statically, at configuration time, either to one or more channels or to one or more PNC entries.

what is switched

Channel

A channel (one network the ECU is connected to, identified by its network handle) has its own state machine in ComM and its own main function. The body gateway has BodyCan (0), ChassisCan (1) and Eth (2).

A user asks for a communication mode (the mode ComM requests for a channel). There are three: COMM_FULL_COMMUNICATION (the channel sends and receives) is the highest, COMM_NO_COMMUNICATION (it neither sends nor receives) the lowest, and between them COMM_SILENT_COMMUNICATION (it receives but does not send). A user may request only full or no communication; silent communication is used by ComM itself on the way to sleep.

The user makes its request with ComM_RequestComMode (the ComM API with which a user requests full or no communication). ComM does not queue requests: the latest request of a user replaces the one before, even if that one was not finished yet.

Mapping: to channels or to PNCs

The example uses both kinds of mapping:

UserMapped toChannels it affects
UserComfortPNC Comfort (16)BodyCan, Eth (the channels of the PNC)
UserLightingPNC Lighting (17)BodyCan
UserChassischannel ChassisCanChassisCan

A user mapped to a PNC reaches the channels through the PNC: a PNC request counts like a user request on each channel of the PNC. So a user may not be mapped to a PNC and also to a channel of that same PNC; the channel is already covered. A user mapped to channels switches exactly those channels and no others.

The highest requested mode wins

Per channel ComM keeps one target mode. If at least one of the requests on that channel asks for full communication, the target is full communication; only when all of them ask for no communication is the target no communication. The users do not see this arbitration: each user only sees its own request and the mode it gets.

The target is not yet the actual mode. Switching a bus takes time (lesson 4), and an inhibition (lesson 11) may hold it back. The actual mode follows the target as soon as the bus state manager reports it.

The ports on the RTE

An SWC does not call ComM_RequestComMode directly. ComM is a service on the RTE and provides two ports for each user:

client-server

UR_{user}: ComM_UserRequest

Operations RequestComMode, GetRequestedComMode, GetCurrentComMode, GetMaxComMode and GetCurrentPNCComMode. The user handle is a port-defined argument of the port, so the SWC never passes it: UR_UserComfort always means UserComfort.

mode switch

UM_{user}: ComM_CurrentMode

A mode switch port (a port through which a module tells an SWC its current mode, and the RTE can start runnables on a change). Its mode group currentMode has the modes of ComMMode: full, silent and no communication. ComM switches it when the mode of the user's channels changes.

For a user with several channels whose modes differ, ComM reports the lowest of them, both on the mode switch port and in GetCurrentComMode. That is the mode the user can rely on for all of its channels.

GetCurrentPNCComMode (the current mode of the PNC of a PNC user) is new in R20-11; 4.4.0 has no ComM_GetCurrentPNCComMode. The ports UR_{user} and UM_{user} and ComM_RequestComMode are the same in 4.4.0, R20-11 and R25-11.

Things to notice. UserComfort and UserLighting are mapped to different PNCs, yet both end on BodyCan: while one of them still requests full communication, releasing the other leaves the channel requested. A user can ask for full or no communication only. The requested mode and the current mode of a channel are two different things.
