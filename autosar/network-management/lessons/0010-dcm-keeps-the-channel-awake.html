Network and Mode Management in AUTOSAR Classic

Network Management

Dcm keeps the channel awake

A tester talking to the ECU must not lose the bus in the middle of a diagnostic session. Dcm therefore tells ComM directly when diagnostics on a channel is active, without being a ComM user.

This lesson shows the interface between Dcm and ComM in both directions, and when Dcm counts diagnostics as active.

Dcm is not a ComM user

A ComM user requests a mode through ComM_RequestComMode and is mapped to channels or PNCs in the configuration. Dcm has an interface of its own instead, with one call for each direction of its state:

Dcm to ComM

ComM_DCM_ActiveDiagnostic

Dcm calls ComM_DCM_ActiveDiagnostic (the report that diagnostics on a channel has become active) with the channel concerned, and again with every request it receives while diagnostics stays active.

Dcm to ComM

ComM_DCM_InactiveDiagnostic

Dcm calls ComM_DCM_InactiveDiagnostic (the report that diagnostics on a channel has ended) when it needs that channel no longer; ComM may then release it.

On a channel with the NM variant FULL, LIGHT or NONE, ComM treats active diagnostics exactly like a request for full communication on that channel: it wakes the channel, and it keeps the channel in COMM_FULL_COM_NETWORK_REQUESTED as long as diagnostics is active, even when no user requests it. On a FULL channel ComM also requests the network from NM, so the whole bus stays awake. On PASSIVE and the slave variants the indication is not treated as a request. If diagnostics needs several channels, Dcm reports each of them.

When Dcm counts diagnostics as active

Dcm keeps a diagnostic state per network:

  • active as soon as a diagnostic request is received on that network, or the session is changed to any session other than the default session (the diagnostic session an ECU is in when no tester has changed it);
  • inactive when the current request is finished, no request of another diagnostic protocol is being processed on that network, and Dcm is in the default session. A request counts as finished when its final response has been sent, or when the response was suppressed.

So a single request in the default session keeps the channel only until its response has been sent. A session change to, for example, an extended session keeps it for the whole session. When the tester stops talking, the session timeout of Dcm (S3Server) brings Dcm back to the default session, and Dcm reports inactive diagnostics on all networks.

An application can tell Dcm that diagnostics shall not keep the ECU awake (Dcm_SetActiveDiagnostic with FALSE). Dcm then does not call ComM_DCM_ActiveDiagnostic any more. After a jump back from the bootloader, Dcm calls ComM_DCM_ActiveDiagnostic at once during its initialization, so that it can answer the tester.

ComM tells Dcm the mode

In the other direction ComM tells Dcm about every change of the channel's mode, with three callbacks:

CallbackWhat Dcm does
Dcm_ComM_FullComModeEnteredSwitches reception and transmission on, including periodic and event-triggered responses
Dcm_ComM_SilentComModeEnteredSwitches all transmission off; reception stays on
Dcm_ComM_NoComModeEnteredSwitches reception and transmission off; Dcm sends nothing more

Dcm waits for Dcm_ComM_FullComModeEntered before it sends a response, but no longer than the response time it owes the tester.

Active diagnostics also has priority over communication inhibition (ComM functions that stop requests from waking or keeping a channel; lesson 11): while a diagnostic session is active, inhibition is suspended, so that the ECU cannot fall asleep under the tester.

Try it

A tester talks to the body gateway on BodyCan. No ComM user needs the channel: it is in COMM_FULL_COM_READY_SLEEP. Pick a case and step through it.

Things to notice. Dcm keeps the channel through its own two calls, not as a ComM user. "Active" means a request is being processed or a non-default session is open; a session keeps the channel much longer than one request. ComM releases the channel only when no user and no active diagnostics needs it.
