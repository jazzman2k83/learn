Sleep: HALT and POLL

With the shutdown target SLEEP, EcuM_GoDownHaltPoll keeps the OS running. EcuM prepares the wakeup, puts the microcontroller into a low-power mode, and the call returns only when the ECU is awake again.

This lesson follows the SLEEP phase from going to sleep, through the two ways of sleeping, to the restart after a wakeup.

Sleep modes

A sleep mode (a configured low-power mode of the ECU) is selected together with the SLEEP target. Each sleep mode names an MCU mode (a low-power setting of the microcontroller driver), the wakeup sources (configured sources of wakeups such as a CAN transceiver or a pin, lesson 33) that may end it, and whether the CPU stops:

CPU stopped

HALT

The CPU is suspended, halted or powered off. EcuM runs no code until a wakeup interrupt brings the CPU back. This is the Halt sequence.

CPU keeps running

POLL

The CPU keeps running, typically at a much lower clock. EcuM loops and asks the wakeup sources that need polling whether they saw a wakeup. This is the Poll sequence.

In the example ECU a sleep mode could allow ECUM_WKSOURCE_BODYCAN and ECUM_WKSOURCE_DOOR_PIN: a frame on body CAN or the door handle wakes the gateway. On a multi-core ECU the SLEEP target puts all cores to sleep.

Going to sleep: GoSleep

The GoSleep sequence (EcuM prepares the hardware for the coming sleep) sets the wakeup states reported to BswM back to none, then calls the callout EcuM_EnableWakeupSources (integrator code that arms the wakeup sources of the sleep mode). Last, EcuM takes an OS resource of its own (RES_AUTOSAR_ECUM, one per core). That locks the scheduler: no other task of the core runs from now on. Unlike the SHUTDOWN phase, the OS is not shut down; the sleep is invisible to it.

No wakeup may be missed. If a wakeup event arrives during GoSleep, EcuM does not enter Halt or Poll at all.

Halt and Poll

In Halt, EcuM calls the callout EcuM_GenerateRamHash (the integrator can compute a checksum of the RAM there) and sets the MCU mode. The CPU stops. A wakeup interrupt starts the check: integrator code calls EcuM_CheckWakeup, EcuM calls the callout EcuM_CheckWakeupHook, and that calls the check function of the driver concerned. The driver reports a real wakeup with EcuM_SetWakeupEvent (a driver tells EcuM that a wakeup source has woken the ECU). After the halt, the callout EcuM_CheckRamHash checks that the RAM did not change during the long sleep.

In Poll, EcuM sets the MCU mode and then loops: it calls the callout EcuM_SleepActivity (integrator code that runs on each pass of the poll loop) and EcuM_CheckWakeupHook for every wakeup source that needs polling, until a wakeup is pending or validated. It reports the new wakeup state to BswM with BswM_EcuM_CurrentWakeup.

Leaving sleep: WakeupRestart

After a wakeup event EcuM leaves the sleep through the WakeupRestart sequence (the steps back to normal operation): it restores the normal MCU mode, reads the pending wakeup events, disarms the sources that woke the ECU with EcuM_DisableWakeupSources (the others stay armed), calls EcuM_AL_DriverRestart to re-initialize the drivers that need it, and releases its resource. Now the other tasks run again, EcuM_GoDownHaltPoll returns E_OK, and the wakeup is validated in the main function of EcuM (lesson 34).

A check started by an interrupt runs under a check-wakeup timer. If all these timers expire without a wakeup event, EcuM goes back to GoSleep and sleeps again, and reports the runtime error ECUM_E_WAKEUP_TIMEOUT. A hardware reset or a power cycle during Halt or Poll is not a wakeup of this kind: the ECU starts again from the STARTUP phase.

Try it

Choose the kind of sleep and step through one night of the example ECU, from EcuM_GoDownHaltPoll to the restart after a frame on body CAN.

In R20-11 and 4.4.0, EcuM_CheckWakeup was the callout itself; from R21-11 it is a function of EcuM that calls the new callout EcuM_CheckWakeupHook. Going back to sleep when all check-wakeup timers expire, and the error ECUM_E_WAKEUP_TIMEOUT, are specified from R21-11 on. Up to 4.3.1 BswM started the two kinds of sleep with EcuM_GoHalt and EcuM_GoPoll.

Things to notice. Both kinds of sleep share GoSleep and WakeupRestart; only the middle part differs. In Halt the wakeup interrupt starts the check; in Poll EcuM's own loop does. The OS keeps running all the time: EcuM only blocks the other tasks with its resource.
