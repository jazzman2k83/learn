Network and Mode Management in AUTOSAR Classic

Network Management

EIRA and ERA

The PNC bits that arrive in NM PDUs are not handed to ComM one by one. NmIf filters them, collects them into two kinds of bit vector, and lets each bit drop back to 0 only when nobody has repeated it for a while.

Lesson 41 used the EIRA bit of a PNC as the trigger that moves the PNC state machine. This lesson shows where that bit comes from: the filter, the two arrays, the timers behind each bit, and the two calls to ComM.

Only the relevant bits count

When CanNm or UdpNm receives an NM PDU with the Partial Network Information Bit set, it takes the PNC bit vector out of the PDU and passes it to NmIf with Nm_PncBitVectorRxIndication (the bus NM hands NmIf the PNC bit vector of a received NM PDU and learns whether it held a relevant request). NmIf first applies the PNC filter mask (per NM channel, one mask byte per byte of the PNC bit vector: only the PNC bits set to 1 in the mask are relevant for this ECU). A received bit counts only where the mask has a 1.

The gateway's masks follow from its PNCs: Comfort (bit 0) and Lighting (bit 1) both use body CAN, so the mask on BodyCan is 0x03; only Comfort uses Ethernet, so the mask on Eth is 0x01. A mask has to let through every PNC that is mapped to the channel; ComM does not check the received bits against its own channel mapping.

ChannelReceived PNC byteMaskRelevantResult
BodyCan0x02 (Lighting)0x030x02relevant request: Lighting counts
Eth0x02 (Lighting)0x010x00nothing relevant
Eth0x03 (both)0x010x01relevant request: only Comfort counts

NmIf tells the bus NM whether a relevant request was found. If not, CanNm drops the NM PDU from further handling: it does not restart the NM-Timeout Timer, so traffic for other PNCs does not keep this ECU awake. Two exceptions keep every NM PDU relevant: the channel is configured to stay awake on all NM PDUs (useful for a gateway), or the transceiver has not yet confirmed that its partial networking works (lesson 43).

Two arrays

From the relevant bits NmIf builds two kinds of PNC bit vector. Each can be switched on by configuration on its own.

one for the whole ECU

EIRA

The EIRA (External and Internal Request Array: one bit per PNC, 1 while any ECU on any channel, this one included, requests the PNC) combines all channels. A bit is set by a relevant bit received on any channel, and by a relevant bit this ECU sends itself. Every ECU with partial networking needs it: it drives the PNC state machine.

one per channel

ERA

The ERA (External Request Array: one bit per PNC and channel, 1 while another ECU on that channel requests the PNC) holds only what was received, separately for each channel. Only a PNC gateway (an ECU that forwards PNC requests from one channel to others, lesson 44) needs it, because it must know where a request came from.

The ECU's own requests reach the EIRA on the way out (they pass the same PNC filter mask). ComM passes the IRA of each channel with Nm_UpdateIRA, and NmIf stores it unfiltered. Each time CanNm or UdpNm sends an NM PDU, it fetches the internal requests with Nm_PncBitVectorTxIndication (the bus NM fetches the PNC bits this ECU requests on the channel, just before it sends an NM PDU) and copies them into the PDU. The bits of that vector that pass the channel's filter mask are stored in the EIRA as requested. They never enter an ERA: an ERA is external only.

The PNC reset timer

A PNC request is not a message that comes once: the requesting ECU repeats it in every NM PDU it sends. So NmIf does not need a "released" message. Each time a PNC bit is stored as requested, its PNC reset timer (the time after which a request that no NM PDU has repeated counts as gone) is restarted with the configured PNC reset time. When the timer runs out without a new request, the bit goes back to 0, "PNC released".

EIRA

One timer per PNC

The EIRA is the same for all channels, so one timer per PNC is enough. A gateway with 6 channels and 8 PNCs needs 8 EIRA timers.

ERA

One timer per PNC and channel

The ERA must tell the channels apart, so the same gateway needs 48 ERA timers: a request must never be mirrored back to the bus it came from.

The reset time sits between two other times. It must be longer than the Message Cycle Time of the bus NM; otherwise a bit requested by only one ECU would drop to 0 between two of its NM PDUs and the EIRA would toggle. It must be shorter than the NM-Timeout Time, so that a bit does not outlive the network: when the timeout runs out the bus NM is already on its way to Prepare Bus-Sleep Mode.

The timers run in the NmIf main function. Its order is fixed: first update the timers, then evaluate the PNC states, then act. The specification gives one possible way of doing it, in which the arrays hold a snapshot of the requests that arrived since the last main function:

Since the last main functionReset timerAction
PNC requestedstopped or elapsedstart the timer; the bit becomes 1: tell ComM
PNC requestedrunningrestart the timer; nothing to tell
not requestedrunningnothing (the timer was already decremented)
not requestedelapsedstop the timer; the bit becomes 0: tell ComM

Reporting to ComM

NmIf calls ComM only when a bit changes, in either direction:

  • ComM_Nm_UpdateEIRA(EIRA): the whole EIRA as a PNC bit vector. ComM copies it into its own EIRA; the PNC state machines react in the next ComM main function (lesson 41).
  • ComM_Nm_UpdateERA(channel, ERA): the ERA of one channel. ComM keeps one ERA per channel and uses it only when it is a PNC gateway and the channel has a gateway type (lesson 44).

In each ComM main function of a channel with PNCs, the requests are handled in this order: ComM users mapped to PNCs of the channel, ComM users mapped to the channel, the ERA (on a PNC gateway), and last the EIRA.

    Calls to ComM

      Up to R20-11 NmIf took no part in this. CanNm and UdpNm each had their own filter mask, EIRA, ERA and reset timers, and passed changed EIRA and ERA values up as I-PDUs through the PduR to COM, where ComM read them as COM signals. R21-11 moved the aggregation into NmIf (as draft, with Nm_UpdateIRA, ComM_Nm_UpdateEIRA and ComM_Nm_UpdateERA), and R22-11 removed the COM path. Lesson 53 shows the older way. The rules themselves (filter, one EIRA timer per PNC, one ERA timer per PNC and channel) are the same.

      Things to notice. A PNC bit counts only where the filter mask of its channel has a 1. The EIRA includes the ECU's own requests, the ERA never does. Nothing says "released": a bit falls to 0 when its reset timer runs out, so the reset time must lie between the NM message cycle and the NM timeout. ComM hears only about changes.
