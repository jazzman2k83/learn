Network and Mode Management in AUTOSAR Classic

Network Management

Why partial networking

Plain network management wakes and keeps awake whole buses. With partial networking, the ECUs on a bus are grouped by function, and only the groups somebody needs are woken and kept awake.

This lesson explains the idea, how a request for a group travels in the NM PDU, and how the number of a group decides its bit. The next lessons show what ComM and NmIf do with these requests.

Whole buses, or parts of them

Without partial networking, one ECU that needs body CAN keeps every ECU on body CAN awake: each of them sees NM PDUs and stays in Network Mode. For a car that is parked or only partly in use this wastes current: when the driver adjusts the seat, the light functions need not run.

A PNC is a logical group of ECUs that have to be active at the same time to realize a distributed function. ComM offers its users the option to wake such a cluster and keep it awake, instead of a whole bus. That gives two things:

less current

Unneeded ECUs keep sleeping

An ECU whose PNCs nobody requests can stay in a low-power mode while the bus carries traffic for others. On CAN this needs transceivers that only wake for relevant NM PDUs, the selective wakeup (the transceiver wakes only on a frame that requests one of its PNCs) of lesson 43.

partial operation

Functions run on their own

A function such as Comfort runs with just the ECUs it needs. Through a PNC gateway (an ECU that forwards PNC requests from one bus to others, lesson 44) a PNC can even span several buses.

In the example, body CAN carries two PNCs: Comfort and Lighting. The BodyControl SWC requests them through its ComM users UserComfort and UserLighting. On this page the Door ECU takes part in Comfort and the Light ECU in Lighting.

Requests travel in the NM PDU

The requests for PNCs are exchanged in the NM PDU that the ECUs send anyway. Part of it is the PNC bit vector: one bit per PNC, set to 1 when the sender requests that PNC. Every ECU that requests at least one PNC keeps sending NM PDUs with its bits, and the others read them.

One bit of the Control Bit Vector tells whether an NM PDU carries this information at all: the Partial Network Information Bit (PNI; set to 1 when partial networking is enabled for the sender's NM channel, so the NM PDU carries a PNC bit vector). An ECU with partial networking ignores NM PDUs whose PNI bit is 0, unless it is configured to stay awake on every NM PDU, as a gateway often is. If the PNI bit is 1, the ECU only reacts to the PNC bits that matter to it.

PNC IDs and their bits

Every PNC has a PNC ID (the number of a PNC, 8 to 511; it fixes the byte and bit of the PNC in the PNC bit vector). ComM supports up to 504 PNCs. The position follows from the ID:

  • byte in the PNC bit vector = (PNC ID div 8) − offset of the PNC bit vector
  • bit in that byte = PNC ID mod 8

The offset is the number of NM PDU bytes in front of the PNC bit vector. So the ID divided by 8 is simply the number of the NM PDU byte, and the remainder the bit in it. On body CAN and Ethernet the gateway uses an offset of 2: byte 0 holds the Source Node Identifier, byte 1 the Control Bit Vector. That gives:

PNCPNC IDID div 8 − 2ID mod 8NM PDU byte
Comfort16byte 0 of the PNC bit vectorbit 02
Lighting17byte 0 of the PNC bit vectorbit 12

With an offset of 2, IDs 8 to 15 would fall into byte 1, the Control Bit Vector: on these buses the smallest usable ID is 16.

Who requests a PNC

Inside an ECU, ComM users request PNCs just as they request channels: UserComfort is mapped to Comfort, UserLighting to Lighting. For each PNC, ComM runs a PNC state machine (one state machine per PNC in ComM that decides whether the PNC is requested, kept awake by others, or off; lesson 41) and passes its own requests to NmIf, which writes them into the NM PDUs. In the other direction NmIf collects the bits that arrive from the other ECUs and hands ComM the result, the EIRA (the external and internal PNC requests combined, one bit per PNC; lesson 42).

In 4.4.0 and R20-11 a PNC ID ranges only from 8 to 63 (4.4.0: up to 56 PNCs), and the position of the PNC information in the NM PDU is configured in each bus NM instead of in NmIf. Up to R20-11 the PNC bits also reach ComM in another way, through COM signals; lesson 53 shows that path.

Things to notice. Partial networking adds no new message: the requests ride in the NM PDUs that keep the bus awake anyway. A PNC is a number, and the number is its place: byte = ID div 8 in the NM PDU, bit = ID mod 8. An ECU only reacts to the PNC bits that concern it, so the others can sleep.
