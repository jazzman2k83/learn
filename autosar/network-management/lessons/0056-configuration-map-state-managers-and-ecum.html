Network Management

Configuration map: CanSM, EthSM and EcuM

The second half of the map: the configuration containers of CanSM, EthSM and EcuM, and the CanIf parameters that decide how a CAN wakeup is validated. Each setting links to the lesson that explains its feature.

The page reads like lesson 55: containers hold configuration parameters, each has a multiplicity and an identifier from chapter 10 of its specification. Here, too, every network is tied to a ComMChannel by a reference.

CanSM

CanSM has two top containers. CanSMGeneral holds the pre-compile switches: the main function period, partial networking support (CanSMPncSupport), the baud rate API and the bus-off delay callout. CanSMConfiguration holds how often and how quickly CanSM repeats a mode request that the CanIf did not confirm (CanSMModeRequestRepetitionMax, CanSMModeRequestRepetitionTime), and one CanSMManagerNetwork per CAN network.

  • CanSM
    • CanSMGeneral 1
    • CanSMConfiguration 1 CanSMModeRequestRepetitionMax, CanSMModeRequestRepetitionTime
      • CanSMManagerNetwork 1..* CanSMComMNetworkHandleRef, CanSMTransceiverId, bus-off recovery
        • CanSMController 1..* CanSMControllerId → CanIf controller
        • CanSMDemEventParameterRefs 0..1 CANSM_E_BUS_OFF, CANSM_E_MODE_REQUEST_TIMEOUT

The bus-off recovery of lesson 22 is five parameters of the network: CanSMBorTimeL1 and CanSMBorTimeL2 (the recovery times of the two levels), CanSMBorCounterL1ToL2 (after how many bus-offs level 2 starts), CanSMBorTimeTxEnsured (how long after a recovery a new bus-off still counts as a failed recovery) and CanSMBorTxConfirmationPolling (ask the CanIf for transmit confirmations instead of waiting that time). CanSMTransceiverId is optional: without a transceiver, CanSM skips the transceiver steps and continues as if the transceiver had confirmed (SWS_CanSM_00560).

EthSM

EthSM is smaller. EthSMGeneral holds the main function period and EthSMDummyMode (EthSM answers ComM with E_OK but does not call the EthIf). Each EthSMNetwork references its ComM channel and one EthIf controller, which stands for an Ethernet controller and, optionally, its transceiver (EthSMEthIfControllerRef).

  • EthSM
    • EthSMGeneral 1 EthSMMainFunctionPeriod, EthSMDummyMode
    • EthSMNetwork 1..* EthSMComMNetworkHandleRef, EthSMEthIfControllerRef, EthSMTcpIpUsed
      • EthSMDemEventParameterRefs 0..1 ETHSM_E_LINK_DOWN

Three Booleans of the network change the behaviour of lesson 23: EthSMTcpIpUsed (default true: EthSM interacts with the TcpIp module; set it to false on a network without TcpIp), EthSMWakeupSleepOnDatalineEnabled (forward a COMM_FULL_COMMUNICATION_WITH_WAKEUP_REQUEST to trigger a wakeup on the data line) and EthSMForwardSilentCommunicationEnabled (forward COMM_SILENT_COMMUNICATION to the EthIf controller).

EcuM

EcuM's configuration has three top containers. EcuMGeneral has the main function period. EcuMFlexGeneral has the EcuM Flex switches: alarm clock present, ECU Mode Handling (EcuMModeHandling), reset loop detection. EcuMConfiguration holds the rest in two parts: EcuMCommonConfiguration (what every EcuM needs) and EcuMFlexConfiguration (what only EcuM Flex needs).

  • EcuM
    • EcuMGeneral 1
    • EcuMFlexGeneral 0..1 EcuMAlarmClockPresent, EcuMModeHandling, EcuMAlarmWakeupSource
    • EcuMConfiguration 1
      • EcuMCommonConfiguration 1
        • EcuMDefaultShutdownTarget 1
        • EcuMDriverInitListZero · EcuMDriverInitListOne 0..1 each EcuMDriverInitItem 1..*
        • EcuMDriverRestartList 0..1
        • EcuMSleepMode 1..256 EcuMSleepModeSuspend, EcuMWakeupSourceMask
        • EcuMWakeupSource 1..32 EcuMValidationTimeout, EcuMComMChannelRef, EcuMComMPNCRef
      • EcuMFlexConfiguration 0..1
        • EcuMFlexUserConfig 1..256
        • EcuMAlarmClock 0..*
        • EcuMDriverInitListBswM 0..*
        • EcuMResetMode · EcuMShutdownCause 1..256 each
        • EcuMGoDownAllowedUsers · EcuMSetClockAllowedUsers 0..1 each

The wakeup source container is the link between EcuM and communication. EcuMComMChannelRef names the channels that a wakeup of this source starts (EcuM calls ComM_EcuM_WakeUpIndication for them), EcuMComMPNCRef the PNCs (ComM_EcuM_PNCWakeUpIndication). EcuMValidationTimeout is the validation timeout; a source without it is not validated (ECUC_EcuM_00148). EcuMWakeupSourceId ranges from 5 to 31, because the first five bits of EcuM_WakeupSourceType are the predefined sources such as ECUM_WKSOURCE_POWER (ECUC_EcuM_00151). Each sleep mode lists the sources it enables in EcuMWakeupSourceMask.

EcuMDefaultShutdownTarget is a container with a parameter of the same name: EcuMShutdownTargetOff, EcuMShutdownTargetReset (EcuM Flex only) or EcuMShutdownTargetSleep, plus the default sleep mode and reset mode (EcuMDefaultSleepModeRef, EcuMDefaultResetModeRef).

CanIf: validating a CAN wakeup

Whether a CAN wakeup is validated at all is a CanIf setting, in CanIfPublicCfg. CanIfPublicWakeupCheckValidSupport (multiplicity 1, default false) switches wakeup validation in CanIf on: CanIf then remembers that a message was received after the wakeup, and CanIf_CheckValidation reports it. CanIfPublicWakeupCheckValidByNM (0..1, default false) narrows that: only received NM messages validate the wakeup, other received PDUs do not (ECUC_CanIf_00741). Which controllers and transceivers can report a wakeup at all is set per device with CanIfCtrlWakeupSupport and CanIfTrcvWakeupSupport.

In 4.4.0 EcuMComMChannelRef could reference only one channel (0..1); since R20-11 a wakeup source can start several channels (0..*). In 4.4.0 EcuMDefaultSleepModeRef and EcuMDefaultResetModeRef were optional; EcuMIgnoreWakeupEvValOffPreOS came with R21-11.

EthSM: EthSMWakeupSleepOnDatalineEnabled is new in R20-11 (not in 4.4.0), EthSMForwardSilentCommunicationEnabled in R21-11 and EthSMTcpIpUsed in R23-11. CanSM in 4.4.0 also had CanSMIcomSupport, which R20-11 no longer has. The CanIf wakeup validation parameters are the same in 4.4.0, R20-11 and R25-11.

Things to notice. CanSM and EthSM each have one container per network, tied to a ComM channel. The wakeup source container in EcuM decides which channels and PNCs a wakeup starts and whether it is validated; CanIf decides what counts as a valid CAN wakeup.
