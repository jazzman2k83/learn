Network and Mode Management in AUTOSAR Classic

Network Management

The NM timers

Four timers drive the CanNm states: how often a node sends, how long it repeats, how long silence must last, and how long the bus calms down. With them you can predict when a bus falls asleep.

Lesson 13 named the transitions; this lesson gives them their times. All nodes of one bus should use the same values for the last two timers, because these decide when everybody sleeps.

Four timers

TimerStartedWhen it runs out
Message Cycle Timewhile the node sends: in the Repeat Message State and the Normal Operation Statethe node sends one NM PDU and starts the timer again
Repeat Message Timeon entering the Repeat Message Statethe node leaves it: to the Normal Operation State if the network is requested, to the Ready Sleep State if it is released
NM-Timeout Timeon entering Network Mode; started again with every NM PDU the node sends or receivesin the Ready Sleep State: Prepare Bus-Sleep Mode. In the other two states it is started again and a runtime error is reported, because the node should have seen NM PDUs
Wait Bus-Sleep Timeon entering Prepare Bus-Sleep ModeBus-Sleep Mode

The NM-Timeout Time is the heart of the algorithm. As long as any node sends, everybody's NM-Timeout Time keeps being restarted, and nobody leaves Network Mode. The Message Cycle Time must therefore be clearly shorter than the NM-Timeout Time, or a node that still needs the bus would let the others time out between two of its PDUs.

Predicting when the bus sleeps

Take the last NM PDU on the bus, sent by whichever node needed the bus longest. Every node in the Ready Sleep State restarts its NM-Timeout Time with that PDU. From then on:

the rule

bus sleep = last NM PDU + NM-Timeout Time + Wait Bus-Sleep Time

If all nodes use the same two values, they reach Bus-Sleep Mode at about the same moment. Small differences come from clock drift, the cycle of the CanNm main function and the time a PDU waits for transmission.

A node that itself just woke stays awake at least for its Repeat Message Time, because it sends throughout the Repeat Message State. So the shortest stay of a node that woke, with nobody needing the bus, is about Repeat Message Time + NM-Timeout Time + Wait Bus-Sleep Time.

Immediate transmissions

When an ECU actively requests the network while the bus sleeps or calms down, it wants the others to wake quickly. CanNm can then start with an immediate transmission (a burst of a configured number of NM PDUs sent with a short cycle of their own, the first one at once). After the burst the node continues with the Message Cycle Time.

This applies when the node's own network request brings it into the Repeat Message State, that is a request in Bus-Sleep Mode or Prepare Bus-Sleep Mode. A node that enters the Repeat Message State through a passive startup or a received NM PDU sends at the normal cycle, and its first NM PDU can be delayed by a configured offset, so that nodes waking at the same moment do not all send at once.

One case is left open. The R25-11 protocol rule for immediate transmissions also names a Repeat Message Request (the control bit that sends every node back into the Repeat Message State; lesson 16) as a trigger, while its rule for the offset names only the network request. The specification does not settle which of the two holds after a Repeat Message Request.

Up to R24-11 the CanNm specification holds the rules for immediate transmissions and the offset itself and names one trigger only: the network request in Bus-Sleep Mode or Prepare Bus-Sleep Mode. R25-11 CanNm refers to the Network Management protocol specification for them.

Try it

Change the timer values (in seconds) and watch the meters and the time line. A new value counts from the next start of that timer. The clock runs in real time; the values are small examples, real projects often use longer ones.

Things to try: wake the bus by the Brake ECU and measure how long the gateway stays awake. Request the network from sleep with 3 immediate transmissions, then with 0. Set the NM-Timeout Time shorter than the Message Cycle Time and release the user and let the Brake ECU keep the bus awake: the gateway now drops into Prepare Bus-Sleep Mode between two of the Brake ECU's PDUs.

Things to notice. Only the NM-Timeout Time and the Wait Bus-Sleep Time decide when a released node sleeps, and they count from the last NM PDU on the bus. The Repeat Message Time is a minimum stay for a node that just entered Network Mode. Immediate transmissions belong to an active request only.
