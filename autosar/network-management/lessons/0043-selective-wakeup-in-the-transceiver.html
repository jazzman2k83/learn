Network and Mode Management in AUTOSAR Classic

Network Management

Selective wakeup in the transceiver

An ECU can only keep sleeping while others talk if its CAN transceiver ignores their traffic. A transceiver with selective wakeup wakes the ECU only for a frame that requests one of its own PNCs.

Lesson 42 showed how an awake ECU ignores NM PDUs for other PNCs. A sleeping ECU has no software running to do that, so the decision moves into the transceiver chip. This lesson shows what CanTrcv configures there, how the software learns that partial networking works, and what CanSM does differently on such a network.

Wake-up pattern or wake-up frame

CanTrcv knows three operation modes:

ModeCommunicationWakeup
CANTRCV_TRCVMODE_NORMALfull bus communicationno further wakeup detection
CANTRCV_TRCVMODE_STANDBYnone; the ECU stays powered if the transceiver controls its supplyby the bus or a local event
CANTRCV_TRCVMODE_SLEEPnone; the ECU may be unpowered; reachable only from standbyby the bus or a local event

A plain transceiver in standby wakes on a wake-up pattern (WUP: bus activity of a defined shape that any CAN traffic produces). On a bus with partial networking that is useless: every NM PDU for any PNC would wake every ECU. A transceiver with selective wakeup (it wakes the ECU only on a frame that requests one of its PNCs) is woken by a wakeup frame (WUF: a CAN frame, normally an NM PDU, that matches the pattern configured in the transceiver) instead.

The pattern is configured in the transceiver: a CAN identifier with an identifier mask (so that a group of frames, such as all NM PDUs, qualifies), the data length, and a data mask over the payload. For AUTOSAR partial networking the data mask is mandatory: it is how the transceiver looks at the PNC bit vector. In this lesson the Light ECU, which belongs to Lighting only, has such a transceiver; its data mask selects bit 1 of NM PDU byte 2, the Lighting bit.

The transceiver detects wakeup frames already in normal mode and keeps a WUF flag (a flag in the transceiver that records a detected wakeup frame). So a frame that arrives while the ECU is just switching to standby is not lost.

    Is partial networking available?

    CanNm filters NM PDUs (lesson 42) only once it knows that the transceiver really does selective wakeup. An ECU whose transceiver does not, wakes on all traffic anyway; it should then also stay awake with the whole network and shut down together with it. So a confirmation travels upwards each time the transceiver is switched to normal mode:

    1. CanTrcv checks the status flags of the transceiver when it is initialized and on every mode change. The POR flag (power-on reset: the transceiver lost its supply and its configuration) makes CanTrcv run the configuration sequence again. The SYSERR flag (a hardware error, for example a configuration error, that made the transceiver disable selective wakeup) means partial networking does not work. At initialization both flags are also reported to EcuM as wakeups, each with its own configured wakeup source.
    2. If the requested mode is normal and SYSERR is not set, CanTrcv calls CanIf_ConfirmPnAvailability (partial networking of a transceiver is confirmed to work; passed on through CanSM to CanNm).
    3. CanIf calls CanSM_ConfirmPnAvailability, and CanSM calls CanNm_ConfirmPnAvailability for the CAN network.
    4. Only now CanNm drops NM PDUs without a relevant PNC request. Before, every NM PDU counts as relevant and restarts the NM-Timeout Timer, so that an ECU with a faulty partial networking transceiver shuts down together with the rest of the network.

    With SYSERR set the transceiver falls back: it wakes on the next wake-up pattern like a plain transceiver. On other hardware errors (for example a frame detection error) it wakes when its internal error counter overflows. Either way the ECU comes up rather than sleeping through a request.

    What CanSM does on a partial network

    CanSM decides per network whether partial networking is supported: it is, when a transceiver is configured for the network and selective wakeup is enabled for it. Then the way to COMM_NO_COMMUNICATION is longer, because no wakeup frame may get lost while the controller and transceiver go down. Step through it:

    Two more pieces belong to partial networking on CAN:

    CanIf

    The first frame is the wakeup frame

    With partial networking, CanIf keeps a PnTxFilter (per CAN controller: while it is on, CanIf accepts only the configured PN filter PDUs, typically the NM PDU, for transmission) per controller. It is on after initialization, after the controller went to sleep, and when the PDU mode goes offline. It turns off with the first transmit confirmation or the first received frame. So the frame that wakes a sleeping bus is the NM PDU with the PNC bits, the frame the other transceivers look for.

    CanNm and CanSM

    No one acknowledges

    If every other ECU on the bus sleeps behind a selective wakeup transceiver that the frame does not wake, nobody may acknowledge the first NM PDU. With partial networking CanNm watches its NM PDU transmissions with a timeout; when it expires, it calls CanSM_TxTimeoutException (CanNm reports that an NM PDU was not confirmed in time on a partial network). CanSM then stops and restarts the CAN controllers of the network.

    Selective wakeup works the same way in 4.4.0 and R20-11: the transceiver has the same wakeup frame settings (identifier, identifier mask, data length and the mandatory data mask), the WUF, POR and SYSERR flags, and the confirmation with CanIf_ConfirmPnAvailability, CanSM_ConfirmPnAvailability and CanNm_ConfirmPnAvailability. CanIf's PnTxFilter and CanSM_TxTimeoutException exist in both releases as well.

    Things to notice. The wakeup decision of a sleeping ECU is made in the transceiver hardware, by a pattern the software configured: identifier, identifier mask and data mask. The software trusts that pattern only after CanIf_ConfirmPnAvailability; until then every NM PDU counts. When anything goes wrong in the transceiver, the ECU wakes up rather than staying asleep.
