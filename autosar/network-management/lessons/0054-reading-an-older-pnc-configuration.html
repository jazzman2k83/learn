Network and Mode Management in AUTOSAR Classic

Network Management

Reading an older PNC configuration

An ECU configured for the COM signal path spreads one PNC over four modules: ComM, the bus NM, PduR and COM. Knowing which containers to open turns such a configuration from a puzzle into a list.

Releases on this page: 4.4.0 to R20-11 (the names were checked in the configuration chapters of both). The last column of the mapping table gives the R25-11 names. R21-11 still has the old parameters, marked obsolete; R22-11 removes them.

This lesson lists the containers and parameters of the old path module by module, fills them in for PNC Comfort (16) of the example gateway, and maps each of them to its R25-11 counterpart in NmIf. The path itself is explained in lesson 53.

Where to look

ComM

  • ComMGeneral
    • ComMPncSupport PNC handling compiled in
    • ComMPncGatewayEnabled PNC gateway on or off
    • ComMPncPrepareSleepTimer
  • ComMConfigSet
    • ComMPncEnabled post-build switch
    • ComMChannel
      • ComMPncGatewayType ACTIVE or PASSIVE
      • ComMNetworkManagement
        • ComMPncNmRequest
    • ComMPnc
      • ComMPncId 8 .. 63
      • ComMChannelPerPnc, ComMUserPerPnc
      • ComMPncComSignal
        • ComMPncComSignalDirection RX or TX
        • ComMPncComSignalKind EIRA or ERA, RX only
        • ComMPncComSignalChannelRef with a PNC gateway
        • ComMPncComSignalRef → ComSignal

CanNm (UdpNm: same names with UdpNm)

  • CanNmGlobalConfig
    • CanNmGlobalPnSupport
    • CanNmComUserDataSupport user data from COM
    • CanNmPnEiraCalcEnabled
    • CanNmPnEiraRxNSduRef → Pdu of the EIRA
    • CanNmPnResetTime seconds
    • CanNmPnInfo
      • CanNmPnInfoOffset, CanNmPnInfoLength bytes
      • CanNmPnFilterMaskByte
        • CanNmPnFilterMaskByteIndex, CanNmPnFilterMaskByteValue
    • CanNmChannelConfig
      • CanNmPnEnabled
      • CanNmPnEraCalcEnabled
      • CanNmPnEraRxNSduRef → Pdu of this channel's ERA
      • CanNmUserDataTxPdu
        • CanNmTxUserDataPduRef

PduR and COM

  • PduR: a routing path from each EIRA and ERA Pdu (source CanNm or UdpNm) to COM, and one from the user data I-PDU of COM to CanNm or UdpNm.
  • COM: a receive I-PDU per EIRA and ERA Pdu, each with one bit vector signal (as long as the PN info) whose notification is ComM_COMCbk_<sn>; and the TX signal inside the NM user data I-PDU, placed on the PN info bytes.

The marked entries exist only for the old path. A quick test of which path a configuration uses: if ComMPncComSignal containers are present and CanNmPnEiraCalcEnabled is set, it is the COM signal path.

In 4.4.0, CanNmPnInfoOffset and CanNmPnInfoLength range from 1 to 7 (an 8-byte NM PDU); R20-11 allows 1 to 63. R20-11 also adds parameters for the drafts of that release, such as CanNmSynchronizedPncShutdownEnabled, CanNmDynamicPncToChannelMappingEnabled and ComMSynchronizedPncShutdownEnabled; they do not belong to the basic COM path.

A worked example: PNC Comfort = 16

Comfort runs on body CAN (CanNm) and on Ethernet (UdpNm); Lighting (17) only on body CAN. The PN info is one byte at offset 2 on both buses. The COM signal names are examples.

Things to notice. The numbers survive a migration: PNC IDs, the offset and length of the PNC bit vector, the mask bytes and the reset time keep their values and change only their container. What disappears is the transport: the EIRA and ERA PDUs, their PduR routes, their COM I-PDUs and signals, and every ComMPncComSignal.
