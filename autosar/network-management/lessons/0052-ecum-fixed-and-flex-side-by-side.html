Network Management

EcuM Fixed and EcuM Flex side by side

The same ECU can be built with EcuM Fixed or with EcuM Flex and BswM. The RUN requests look alike in both; who acts on them does not.

Releases on this page. The EcuM Fixed column describes AUTOSAR 4.0.3 to 4.3.1. The EcuM Flex column describes R25-11; where Flex differed in 4.3.1 or older, the text says so. In 4.3.1 both variants are specified, so a 4.3.1 project may use either one.

This lesson compares the two variants point by point, lists the APIs that exist in only one of them, maps each Fixed concept to its Flex and BswM counterpart, and shows how to read and migrate an EcuM Fixed project.

Who owns the state machine

EcuM Fixed

EcuM owns it

The states and their order are part of the standard: STARTUP, RUN with APP_RUN and APP_POST_RUN, SHUTDOWN, SLEEP, WAKEUP, OFF (lesson 51). EcuM runs them in EcuM_MainFunction and tells BswM the current state through BswM_EcuM_CurrentState; BswM only follows.

EcuM Flex + BswM

BswM decides, EcuM executes

EcuM keeps only the STARTUP phase, the SHUTDOWN phase, the SLEEP phase and the wakeup handling. In the UP phase the ECU's modes are whatever the integrator configures as BswM rules and action lists (lessons 25 and 27). With ECU Mode Handling, BswM sets the EcuM state with EcuM_SetState.

How shutdown is decided

EcuM Fixed

A fixed condition

EcuM leaves RUN when no RUN request is placed, EcuMRunMinimumDuration is over and ComM_GetState reports every channel idle. It shuts down when the last POST_RUN request is released. The shutdown target comes from EcuM_SelectShutdownTarget or the configured default.

EcuM Flex + BswM

A configured rule

EcuM only reports the RUN request protocol to BswM with BswM_EcuM_RequestedState. A BswM rule combines this with whatever else matters (ComM modes, NvM, application modes); its action list selects the target and calls EcuM_GoDownHaltPoll. Nothing shuts the ECU down unless such a rule exists (lessons 28 and 29).

In 4.3.1 and older, EcuM Flex has three calls instead of one: EcuM_GoDown, EcuM_GoHalt and EcuM_GoPoll. 4.4.0 replaced them with EcuM_GoDownHaltPoll, which acts on the selected shutdown target.

RUN requests in both

The four calls EcuM_RequestRUN, EcuM_ReleaseRUN, EcuM_RequestPOST_RUN and EcuM_ReleasePOST_RUN have the same names, service IDs and parameter (the EcuM user) in both variants, and SWCs reach them through the same EcuM_StateRequest port interface. That is why an SWC usually needs no change. The difference lies behind the call: in EcuM Fixed a placed RUN request holds the ECU in RUN by itself; in EcuM Flex it is only an input to a BswM rule.

Try it

The same event in both variants: the last SWC releases RUN while ChassisCan is already in no communication. Step through it call by call, then switch the variant. The EcuM Flex story shows one possible BswM configuration; the actions are whatever the integrator configures.

Reading and migrating an EcuM Fixed project

  1. Recognise it. The EcuM configuration contains EcuMFixedGeneral and EcuMConfiguration/EcuMFixedConfiguration; the code calls EcuM_OnEnterRun and its siblings, or ComM_GetState.
  2. List the RUN users. Every EcuMFixedUser becomes an EcuMFlexUser. The SWC calls stay as they are.
  3. Write the RUN rule. Make the implicit conditions explicit: RUN request status, the ComM modes of the channels that used to keep the ECU alive, the minimum duration (a BswM timer). Each condition that EcuM Fixed checked by itself becomes a mode request in BswM.
  4. Move the calls. ComM_CommunicationAllowed for the channels of EcuMComMCommunicationAllowedList, the code of the RUN and shutdown callouts and the shutdown itself move into action lists.
  5. Replace what has no equivalent. TTII and EcuM_KillAllRUNRequests need their own design with the alarm clock and BswM rules.
  6. Check the wakeup side. Wakeup sources, validation and ComM_EcuM_WakeUpIndication work as before; the wakeup reaction becomes a BswM rule.

Things to notice. An SWC that places RUN requests sees almost no difference between the variants; the difference is that EcuM Fixed obeys the requests, while EcuM Flex only passes them on to BswM. Everything that EcuM Fixed did implicitly (keeping RUN for ComM, allowing communication, the minimum RUN time, shutting down) has to be written down as BswM rules when moving to EcuM Flex.
