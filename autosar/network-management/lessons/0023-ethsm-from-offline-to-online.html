Network Management

EthSM: from OFFLINE to ONLINE

On Ethernet, a request for full communication is not done when the controller runs. EthSM waits for a working cable connection and then for IP communication, and only then tells ComM that the channel Eth has full communication.

Three conditions for full communication

EthSM is the bus state manager for Ethernet: one state machine per Ethernet network, which on the example ECU is the ComM channel Eth. (A VLAN counts as a network of its own and gets its own ComM channel.) EthSM controls the Ethernet controller through EthIf, and it needs three things before it reports COMM_FULL_COMMUNICATION:

1 · controller

Controller active

EthSM asks EthIf to set the controller mode to ETH_MODE_ACTIVE; EthIf switches the controller and the transceiver on.

2 · link

Link up

The EthTrcv (Ethernet Transceiver Driver: controls the PHY between controller and cable) reports a link state (whether the transceiver has a working connection to its link partner) of ETHTRCV_LINK_STATE_ACTIVE.

3 · IP

IP communication

TcpIp reports TCPIP_STATE_ONLINE: IP communication is available, which needs an IP address for the controller. Lesson 24 shows what this starts above.

EthIf polls the link state in a main function and reports every change to EthSM (EthSM_TrcvLinkStateChg); with a switch, EthIf reports the link of the switch port towards the controller. TcpIp reports its state with EthSM_TcpIpModeIndication. EthSM stores both and acts on them at the latest in its next main function.

EthSM has no silent communication of its own. Its two main states are ETHSM_NO_COMMUNICATION and ETHSM_FULL_COMMUNICATION, with three sub-states each.

Up. A full communication request in OFFLINE sets the controller active (WAIT_TRCVLINK). When the link comes up, EthSM asks TcpIp for TCPIP_STATE_ONLINE (WAIT_ONLINE). When TcpIp reports online, EthSM enters ONLINE and calls ComM_EthSM_ModeIndication with full communication.

Link lost. If the link goes down in ONLINE, EthSM asks TcpIp to put its state on hold and enters ONHOLD. ComM is not told: for a short break in the cable the channel stays in full communication, and TcpIp keeps its address. If the link comes back, EthSM asks for online again and returns to ONLINE. If TcpIp reports offline instead, EthSM drops to WAIT_TRCVLINK and reports no communication to ComM. In this transition, and when the link comes back in WAIT_TRCVLINK, EthSM can report a link-down event to DEM as failed and passed, if it is configured.

Down. A silent or no communication request in ONLINE leads to WAIT_OFFLINE. For silent communication, EthSM can switch the controller to transmit off (ETH_MODE_ACTIVE_TX_OFFLINE), if that forwarding is configured; for no communication it asks TcpIp for offline. When TcpIp reports offline, EthSM sets the controller down, enters OFFLINE and reports no communication to ComM. A full communication request in WAIT_OFFLINE turns the way round again.

Every time EthSM enters a sub-state it reports it to BswM with BswM_EthSM_CurrentState, so BswM rules can react to the sub-state, not only to the ComM mode.

    When the Ethernet wakes the ECU

    With Ethernet hardware following the OPEN Alliance specification OA TC10, the PHY can detect a wakeup on the cable and also send one. A sleeping ECU then reports the wakeup through the usual chain of EcuM (lessons 33 to 35): the interrupt or a poll leads to EcuM_CheckWakeup, the integration code calls EthIf_CheckWakeup, EthIf asks the transceiver or switch driver to check its hardware, and the driver reports the wakeup to EcuM. An ECU with an Ethernet switch has many ports to check, so the interrupt only marks the transceivers to be checked later, in the transceiver's main function.

    To wake the link partners, ComM can request COMM_FULL_COMMUNICATION_WITH_WAKEUP_REQUEST. If wakeup and sleep on the data line are configured, EthSM then sets the controller to ETH_MODE_ACTIVE_WITH_WAKEUP_REQUEST, in any sub-state, so that the hardware sends a wakeup on the network.

    EcuM describes the Ethernet wakeup sequence only since R21-11; in R20-11 and 4.4.0 it is not part of the EcuM specification. The request with wakeup (COMM_FULL_COMMUNICATION_WITH_WAKEUP_REQUEST) came with the reworked EthSM state machine of R20-11 and does not exist in 4.4.0. Forwarding silent communication to the controller (transmit off in WAIT_OFFLINE) exists only since R21-11; in R20-11 and 4.4.0 a silent request does not switch off transmission.

    Things to notice. ComM gets full communication only in ONLINE, so only once IP works, not when the controller or the link is up. A lost link first leads to ONHOLD, where ComM still sees full communication; only when TcpIp gives up does ComM see no communication. Going down waits for TcpIp to report offline before the controller is switched off.
