Shutdown targets

When BswM decides that the ECU should stop, it first tells EcuM where the ECU is to go: switched off, reset, or asleep. Then one call makes EcuM go there.

This lesson shows the three destinations, how one is selected, how a cause is recorded, and what EcuM does on the way to off or reset.

Three shutdown targets

A shutdown target (the state the ECU goes to when it leaves the UP phase: OFF, RESET or SLEEP) is one of the states in which no code runs. Two of them come in several variants, configured per ECU.

ECUM_SHUTDOWN_TARGET_OFF

OFF

The ECU switches its own power off. Not every hardware design can do that. Only wakeup sources with integrated power control can wake an ECU that is off.

ECUM_SHUTDOWN_TARGET_RESET

RESET

The ECU restarts. A reset mode (one configured way to reset) says how: at least ECUM_RESET_MCU (through Mcu_PerformReset), ECUM_RESET_WDG (through WdgM_PerformReset) and ECUM_RESET_IO (by toggling an I/O line).

ECUM_SHUTDOWN_TARGET_SLEEP

SLEEP

The ECU stays powered and waits for a wakeup. A sleep mode (a configured low-power mode of the microcontroller, lesson 30) says which one.

After a reset the shutdown target is the default from the configuration. Before BswM sends the ECU to sleep it must make sure that a SLEEP target has been selected.

Selecting a target and a cause

EcuM_SelectShutdownTarget (stores the target and its reset or sleep mode for the next shutdown) only stores the value; nothing is prepared yet. EcuM resolves no conflicts: if several callers select a target, the last one wins, so a project usually lets only one place do it. BswM calls it from an action list; an SWC can call it through the RTE port EcuM_ShutdownTarget. That port has no operation to start a shutdown.

EcuM_GetShutdownTarget reads the target for the next shutdown. EcuM_GetLastShutdownTarget (returns the target of the previous shutdown) tells software after startup where the ECU came from: from a sleep, a reset or off.

A shutdown cause (the recorded reason for a shutdown) is stored with EcuM_SelectShutdownCause and read with EcuM_GetShutdownCause. The standard values are ECUM_CAUSE_UNKNOWN, ECUM_CAUSE_ECU_STATE (the ECU state machine entered a state for shutdown), ECUM_CAUSE_WDGM (the Watchdog Manager detected a failure) and ECUM_CAUSE_DCM (Dcm requests a shutdown because of a service request); the configuration can add more.

Going down: EcuM_GoDownHaltPoll

EcuM_GoDownHaltPoll takes the ECU to the selected target. Its parameter is the EcuM user that calls it, normally BswM in an action list. For the targets RESET and OFF, only users allowed by configuration may call it; otherwise it returns E_NOT_OK. For RESET and OFF the call never returns. For SLEEP it returns E_OK when the ECU is awake again.

With RESET or OFF the SHUTDOWN phase runs in two parts, before and after the OS is shut down:

  • The OffPreOS sequence (shutdown steps while the OS still runs): the callout EcuM_OnGoOffOne (a callout is a function the integrator fills in), then de-initialization of BswM and of the BSW Scheduler (SchM), a check for wakeup events, and finally ShutdownOS.
  • The OS calls its shutdown hook, which calls EcuM_Shutdown. That starts the OffPostOS sequence (the last steps after the OS has stopped): the callout EcuM_OnGoOffTwo, then EcuM_AL_Reset with the reset mode, or EcuM_AL_SwitchOff.

A wakeup during shutdown is not lost. EcuM completes the shutdown and restarts at once: if the check in OffPreOS finds wakeup events, it selects RESET with the default reset mode. With the SchM already stopped, no validation can run any more, so the configuration decides which events count: all pending ones, or only those that need no validation.

Try it

Pick a target and step through the call sequence. Tick the wakeup box to see the target change during shutdown.

Up to 4.3.1 EcuM Flex had three calls instead of one: EcuM_GoDown (off or reset, with the module ID of the caller), EcuM_GoHalt and EcuM_GoPoll (the two kinds of sleep). 4.4.0 replaced them with EcuM_GoDownHaltPoll; in 4.4.0 its parameter is still the caller's module ID (uint16 caller), from R20-11 it is an EcuM_UserType. In R20-11 and older the OffPreOS check always takes all pending wakeup events; the choice to consider only events that need no validation came in R21-11.

Things to notice. Selecting a target does nothing by itself; EcuM_GoDownHaltPoll acts on whatever was selected last. RESET and OFF never return; SLEEP returns after the wakeup. A wakeup during shutdown turns OFF into RESET, so the ECU starts again at once.
