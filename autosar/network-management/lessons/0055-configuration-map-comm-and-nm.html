Network Management

Configuration map: ComM and NM

Every feature of the earlier lessons is switched on, sized and timed somewhere in the configuration of ComM, NmIf, CanNm and UdpNm. This page is the map: where each setting lives, how often it may appear, and which lesson explains what it does.

The names on this page are the names a configuration tool shows. They are defined in chapter 10 of each module's specification. Each entry there has an identifier such as ECUC_ComM_00568; the map below gives it, so you can look the entry up.

How a module configuration is built

A module's configuration is a tree. At the top is the module (ComM, Nm, CanNm, UdpNm). Below it are configuration containers (named groups of settings, which can hold further containers), and in them the configuration parameters (single settings with a type and a range: a Boolean, a number of seconds, an enumeration, or a reference to a container of another module). Each container and parameter has a multiplicity (how many times it may exist below its parent): 1 means exactly once, 0..1 optional, 1..* at least once, 0..255 up to 255 times.

A container with a multiplicity above one is the configuration of one thing per instance: one ComMChannel per channel, one ComMUser per ComM user, one CanNmChannelConfig per CAN channel with CanNm. The channels of all these modules are tied together by references to the ComMChannel: every NM and every bus state manager channel names the ComM channel it belongs to.

ComM

ComMGeneral holds the switches that apply to the whole module: partial networking (ComMPncSupport), the PNC gateway, synchronized PNC shutdown, the inhibition features and the minimum time a channel stays requested (ComMTMinFullComModeDuration, used only with the NM variants LIGHT and NONE). ComMConfigSet holds the instances: users, channels and PNCs.

  • ComM
    • ComMGeneral 1
    • ComMConfigSet 1
      • ComMUser 0..65535
      • ComMChannel 1..256 ComMBusType, ComMChannelId, ComMPncEnabled, …
        • ComMNetworkManagement 1 ComMNmVariant, ComMNmLightTimeout, ComMPncNmRequest
        • ComMUserPerChannel 0..255 ComMUserChannel → ComMUser
      • ComMPnc 0..504 ComMPncId, ComMChannelPerPnc, ComMUserPerPnc

Some rules in the definitions are worth knowing. ComMNmVariant must be NONE on a channel whose ComMBusType is COMM_BUS_TYPE_INTERNAL, LIGHT on a managed channel and FULL on a managing channel (ECUC_ComM_00568). A ComMPncId lies between 8 and 511 (ECUC_ComM_00874); together with the bit vector offset it decides in which byte and bit of the NM PDU a PNC is carried (lesson 57).

New in R25-11: ComMPncEnabled is a parameter of each ComMChannel (ECUC_ComM_00901). Partial networking is now switched on per channel, not once for the whole configuration set.

NmIf

The configuration of NmIf is called Nm. Its NmGlobalConfig has three containers: NmGlobalConstants (the number of channels), NmGlobalProperties (main function period and the partial networking values that are the same for every channel) and NmGlobalFeatures (pre-compile switches: NM coordinator, Remote Sleep Indication, user data, car wakeup, partial networking). Two of these switches exclude each other: NmPartialNetworkSupportEnabled may be true only if NmCoordinatorSupportEnabled is false (ECUC_Nm_00253); an NmIf supports either the NM coordinator or partial networking. The example gateway uses partial networking, so its coordinator switch is off. Each NmChannelConfig belongs to one ComM channel and says which bus NM serves it, through the choice container NmBusType.

  • Nm
    • NmGlobalConfig 1
      • NmGlobalConstants 1
      • NmGlobalProperties 1 NmPncBitVectorOffset, NmPnResetTime, NmPnEiraCalcEnabled
      • NmGlobalFeatures 1
    • NmChannelConfig 1..* NmComMChannelRef, NmPnEnabled, NmPncBitVectorLength, NmPnEraCalcEnabled
      • NmBusType 1 (choice) NmStandardBusNmConfig or NmGenericBusNmConfig
      • NmPnFilterMaskByte 0..63

Where the PNC bit vector sits in the NM PDU is configured here, not in the bus NMs: NmPncBitVectorOffset once for all channels, NmPncBitVectorLength per channel. The definition requires that the offset equals the number of system bytes, or that offset plus length equals the length of the NM PDU (ECUC_Nm_00252). The PNC filter mask bytes (NmPnFilterMaskByte) also belong to the NM channel; their index must stay below NmPncBitVectorLength (ECUC_Nm_00255).

NmStandardBusType names the bus NM: NM_BUSNM_CANNM, NM_BUSNM_UDPNM, NM_BUSNM_FRNM, NM_BUSNM_J1939NM or NM_BUSNM_LOCALNM. The last one is allowed only on a coordinated channel, that is a channel with an NmCoordClusterIndex (ECUC_Nm_00220).

CanNm and UdpNm

CanNmGlobalConfig holds the feature switches (passive mode, bus load reduction, communication control, partial networking with CanNmGlobalPnSupport) and the main function period. Each CanNmChannelConfig holds the timers, the node identifier, the positions of the system bytes and the PDUs. The timers of lesson 14 are configuration parameters one to one:

The positions of the Source Node Identifier and the Control Bit Vector are enumerations: CanNmPduNidPosition and CanNmPduCbvPosition each take CANNM_PDU_BYTE_0, CANNM_PDU_BYTE_1 or CANNM_PDU_OFF. They may not use the same byte, and with node detection switched on the Control Bit Vector may not be off (ECUC_CanNm_00026). Lesson 57 shows the bytes and bits.

UdpNm is configured the same way, with UdpNm in place of CanNm. The differences are small: UdpNm has no bus load reduction parameters, its main function period is set per channel (UdpNmMainFunctionPeriod in UdpNmChannelConfig), its node identifier is optional (UdpNmNodeId, multiplicity 0..1), its UdpNmRemoteSleepIndTime is mandatory, and UdpNmGlobalConfig holds the number of channels (UdpNmNumberOfChannels).

In R24-11 and earlier, ComMPncEnabled (then ECUC_ComM_00878) was a parameter of ComMConfigSet: one switch for all channels. R25-11 moves it into ComMChannel as ECUC_ComM_00901.

In 4.4.0 and R20-11 the PNC bit vector was configured in the bus NM: CanNmPnInfo in CanNmGlobalConfig with CanNmPnInfoOffset, CanNmPnInfoLength and CanNmPnFilterMaskByte, plus CanNmPnResetTime, CanNmPnEiraCalcEnabled and CanNmPnEraCalcEnabled (the same with UdpNm names). R21-11 added NmPncBitVectorOffset, NmPncBitVectorLength, NmPnResetTime, NmPnEnabled and NmPnFilterMaskByte to NmIf as draft and marked the CanNm and UdpNm parameters obsolete; R22-11 removed them from CanNm and UdpNm.

Up to R21-11, ComMPnc had ComMPncComSignal containers that referenced the COM signals carrying EIRA and ERA (lesson 53); R22-11 removed them. In 4.4.0 CanNmWaitBusSleepTime and UdpNmNodeId were mandatory (multiplicity 1), and ComMManageReference could exist only once per channel (0..1; 0..* since R21-11).

Things to notice. The ComM channel is the anchor: NmIf, CanNm and UdpNm channels all reference it. The layout of the PNC bit vector is an NmIf setting; the offset is one value for all channels, the length is per channel. Most timers of NM are per channel; most feature switches are global and fixed at pre-compile time.

New terms in this lesson

TermMeaning
configuration containerA named group of configuration settings in a module's configuration; it can hold parameters and further containers
configuration parameterOne setting in a container, with a type and a range: a Boolean, a number, an enumeration or a reference
multiplicityHow many times a container or parameter may exist below its parent, for example 1, 0..1 or 1..*
ComMChannelThe ComM container for one channel: bus type, channel ID, NM variant, users and PNC settings of that channel
ComMUserThe ComM container for one ComM user, with its identifier
ComMPncThe ComM container for one PNC: its PNC ID, its channels and its users
NmChannelConfigThe NmIf container for one NM channel: the ComM channel, the bus NM, PN and coordination settings
CanNmChannelConfigThe CanNm container for one CAN channel: timers, node identifier, positions of the system bytes and the NM PDUs
