Network and Mode Management in AUTOSAR Classic

Network Management

A PNC request across the gateway

PNC Comfort lives on body CAN and Ethernet. A request for it, made by UserComfort inside the gateway or by the Head unit on Ethernet, ends up as a bit in the PNC bit vector of the gateway's NM PDUs, on one bus or on both.

This flow follows one PNC request through ComM, NmIf, CanNm and UdpNm, in the R25-11 way: PNC bits travel between ComM and the bus NMs through NmIf, in the IRA, the ERA and the EIRA. Every call, its caller and its order are taken from the R25-11 specifications; where they leave a choice to the integrator, the step says so.

The starting point

The gateway runs, and all three channels are in COMM_FULL_COMMUNICATION. UserLighting requests PNC Lighting, so PNC 17 is in COMM_PNC_REQUESTED and the gateway's NM PDUs on body CAN carry 0x02 in byte 2, the one byte of the PNC bit vector (Comfort = bit 0, Lighting = bit 1, lesson 3). PNC Comfort is in COMM_PNC_NO_COMMUNICATION. The gateway function of ComM is on, and body CAN and Ethernet are both active PNC gateway channels: the gateway is the top-level PNC coordinator of Comfort and Lighting (lesson 44).

Two ways in, the same way out

inside · lessons 5, 41

A local user

ComM_RequestComMode of UserComfort moves PNC Comfort to COMM_PNC_REQUESTED in the next ComM main function. ComM sets the Comfort bit in the IRA of both channels and passes each with Nm_UpdateIRA.

outside · lessons 42, 44

A request on Ethernet

The Head unit's NM PDU arrives in UdpNm, which hands the bits to NmIf. NmIf updates the ERA of Eth and the EIRA and tells ComM with ComM_Nm_UpdateERA and ComM_Nm_UpdateEIRA. The ERA bit makes the gateway request Comfort itself.

out · lessons 15, 20

Into the NM PDUs

Each time CanNm or UdpNm is about to send, it fetches the IRA of its channel from NmIf with Nm_PncBitVectorTxIndication and copies it to byte 2. That is all it takes for the Door ECU or the Head unit to see the request.

Why the Head unit's request is not sent back to it

ComM decides per channel whether it sets the bit in that channel's IRA. For a local request it sets it on every channel of the PNC. For a request from another ECU, the gateway type of the channels decides: the bit goes out on all active channels, and on a passive channel only if the request came in on an active one. A request that comes in on a passive channel is therefore never mirrored back on it, which keeps two coordinators from holding each other's requests forever.

In the example ECU Eth is an active channel (lesson 3), so the gateway also repeats the Head unit's bit on Ethernet. The diagram shows one variant at that step as well, which is not the example's configuration: if Ethernet were a passive PNC gateway channel, with the Head unit coordinating above the gateway, the Head unit's request would reach body CAN only.

What the specification leaves to the integrator

  • Which I-PDU groups belong to a PNC, and the BswM rule that starts them on BswM_ComM_CurrentPNCMode.
  • Whether ComM calls Nm_NetworkRequest again for a PNC request on a channel that is already in full communication. ComM does it only if configured; with a matching CanNm setting the network request then starts immediate transmission of NM PDUs instead of waiting for the next cycle.
  • The PNC filter mask, the PNC reset timer and the gateway type of each channel.

This page shows the R25-11 path only. Up to R20-11 (and in 4.4.0) ComM did not call Nm_UpdateIRA, and NmIf took no part: CanNm and UdpNm computed EIRA and ERA themselves, and ComM read them and sent its own PNC requests through COM signals (lesson 53). The NmIf path came as draft in R21-11 and replaced the COM path in R22-11. In 4.4.0 and R20-11 CanNm also calls CanIf_Transmit directly; the LSduR between them exists from R24-11.

Things to notice. The bus NMs never decide anything about PNCs: they pass received bits up to NmIf and fetch the bits to send from NmIf. ComM handles the PNC request in the main function of each channel it affects. A local request goes out on both buses; a request from the Head unit is mirrored onto body CAN, and back onto Ethernet because Ethernet is an active channel in the example; in the passive variant it would not be.
