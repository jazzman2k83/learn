The alarm clock

Some jobs must run hours after the car was parked, while the ECU sleeps. EcuM can keep a clock running through the sleep and wake the ECU at a set time.

This lesson shows the clock that EcuM keeps, the alarms its users set on it, and how the clock goes on counting while the ECU sleeps.

The EcuM clock and the alarms

The alarm clock (an optional EcuM service that wakes the ECU from sleep at a set time) is built from two parts:

  • The EcuM clock (time in seconds since the battery was connected): it counts in the UP phase and in the SLEEP phase, and where the hardware allows, an ECU reset does not reset it.
  • Alarms: each EcuM user may own one user alarm clock (a wakeup time of one user). No user can change the alarm of another. The master alarm clock (the wakeup time EcuM acts on) is always the earliest of the user alarms.

The service has one wakeup source of its own, usually a timer of the microcontroller that can wake it. Alarms are set and read only in the UP phase; they take effect in the SLEEP phase.

Setting and aborting alarms

CallWhat it does
EcuM_SetRelWakeupAlarmSets the user's alarm a number of seconds from now
EcuM_SetAbsWakeupAlarmSets the user's alarm to an absolute time of the EcuM clock; a time already passed returns ECUM_E_PAST
EcuM_AbortWakeupAlarmCancels the user's alarm; without one it returns ECUM_E_NOT_ACTIVE. The master alarm moves to the next earliest user alarm.
EcuM_GetCurrentTime, EcuM_GetWakeupTimeRead the EcuM clock and the master alarm (0xFFFFFFFF: no alarm active)
EcuM_SetClockSets the EcuM clock; only users allowed by configuration, meant for testing alarms that take days

An alarm earlier than the current master alarm moves the wakeup time forward. A later one leaves the wakeup time as it is, and the call returns ECUM_E_EARLIER_ACTIVE: an earlier alarm is already set.

Counting through the sleep

In the UP phase the main function of EcuM advances the clock from an OS counter. During sleep EcuM counts differently: in HALT a timer wakes the CPU, ideally once a second. EcuM adds the time and goes straight back to sleep, without the WakeupRestart sequence, unless the clock has reached the master alarm. In POLL the clock can be advanced in EcuM_SleepActivity. Only when the master alarm is reached does the ECU really wake up; then the BswM rules decide whether it starts fully or goes back to sleep.

When the ECU leaves the sleep, for the alarm or for any other wakeup, EcuM cancels all user alarms and the master alarm. They are also cancelled in the startup and in the OffPreOS sequence of a shutdown. A user that needs another wakeup sets its alarm again before the next sleep.

Set an alarm, then let the ECU sleep.

Things to notice. The master alarm is always the earliest user alarm, and an abort moves it to the next one. During sleep the timer wakes the CPU every second, yet the ECU only really wakes at the master alarm. Any real wakeup clears every alarm.
