Network and Mode Management in AUTOSAR Classic

Network Management

Going to sleep

The last ComM user of the body gateway releases its request. ComM releases the network, the NM coordinator shuts the three buses down together, each bus NM runs to Bus-Sleep Mode, and BswM sends the ECU to sleep, unless a RUN request still holds it.

This is the way back from the first two flows. Every call, its caller and its order are taken from the R25-11 specifications; where they leave a choice to the integrator, the step says so. The diagram follows chassis CAN in detail; body CAN and Ethernet run the same way at their own moments.

The starting point

All three buses are awake. UserComfort and UserLighting released their requests earlier; the other ECUs no longer request PNCs, so both PNCs are back in COMM_PNC_NO_COMMUNICATION, and BodyCan and Eth are in COMM_FULL_COM_READY_SLEEP. ComM released those two networks long ago, but the NM coordinator still holds them: ComM still requests ChassisCan for UserChassis, and one need inside the gateway keeps every awake bus of the cluster requested (lesson 37). The Door ECU, the Light ECU, the Brake ECU and the Head unit have stopped sending NM PDUs, so each bus NM has reported a Remote Sleep Indication.

The four phases

ComM · lessons 6, 7

Release

With no request left, ChassisCan enters COMM_FULL_COM_READY_SLEEP and ComM calls Nm_NetworkRelease. The bus does not stop yet; ComM has only stopped asking for it.

NmIf · lesson 38

Coordinated shutdown

Now every bus of the cluster is released by ComM and has reported remote sleep. The coordinator starts the coordinated shutdown: a shutdown timer per bus, then CanNm_RequestBusSynchronization and CanNm_NetworkRelease.

CanNm · lessons 13, 14

Down through the NM states

Ready Sleep State until the NM-Timeout Time runs out, Prepare Bus-Sleep Mode for the Wait Bus-Sleep Time, then Bus-Sleep Mode. Each mode change reaches ComM through NmIf.

ComM, CanSM, BswM, EcuM · lessons 21, 28–30

Silent, off, asleep

ComM goes through COMM_SILENT_COMMUNICATION to COMM_NO_COMMUNICATION, CanSM switches the hardware off, and a BswM rule calls EcuM_GoDownHaltPoll once nothing needs the ECU any more.

Three buses, one moment

With the shutdown times of lesson 38 (global coordinator time 4 s), NmIf releases Eth at once, BodyCan after 0.5 s and ChassisCan after 1.5 s. Each bus then runs the steps drawn here for chassis CAN, and all three reach Bus-Sleep Mode at about the same time. Body CAN differs in one detail: it uses partial networking, so CanSM leaves the transceiver with selective wakeup armed (lesson 43), ready for the next flow of lesson 48.

A request in the middle stops all this. If a ComM user asks for a channel while the shutdown runs, ComM calls Nm_NetworkRequest, the coordinator aborts the shutdown and requests the buses that are not yet asleep again (lesson 39). A bus that already sleeps is woken actively, as in lesson 47.

What the specification leaves to the integrator

  • The BswM rule that decides on sleep. A typical rule waits until all channels are in COMM_NO_COMMUNICATION and EcuM reports that the last RUN request is released; what it checks is configuration.
  • Its action list: stopping the I-PDU groups (already on the silent or no communication mode), ComM_CommunicationAllowed with FALSE, EcuM_SelectShutdownTarget with the target SLEEP and a sleep mode, then EcuM_GoDownHaltPoll. The specification only requires that a sleep target is selected before EcuM_GoDownHaltPoll.
  • Whether BswM evaluates the rules at once or in its main function, and the callout EcuM_EnableWakeupSources that arms the wakeup sources of the chosen sleep mode.

The flow is the same in 4.4.0 and R20-11: the coordinator, the CanNm states, the ComM transitions and EcuM_GoDownHaltPoll (new in 4.4.0). One detail of the coordinator changed in R25-11: up to R24-11 a shutdown timer is started for every awake channel of the cluster, since R25-11 for every awake, actively coordinated one; for the example gateway, whose channels are all actively coordinated, that makes no difference. Up to 4.3.1 BswM started the sleep with EcuM_GoHalt or EcuM_GoPoll instead; with EcuM Fixed, EcuM itself decided when to leave RUN (lesson 51).

Things to notice. Releasing the network is not switching it off: after Nm_NetworkRelease the gateway may stay awake for seconds, held by the coordinator and the NM timers. The way down is driven by indications from below (Prepare Bus-Sleep Mode, then Bus-Sleep Mode), each answered by ComM with a new request to CanSM. Buses asleep and ECU asleep are two decisions: the buses sleep by NM, the ECU sleeps only when a BswM rule says so.
