Network and Mode Management in AUTOSAR Classic

Network Management

The example ECU: a body gateway

Every later lesson uses one ECU as its example: a gateway on three buses with one SWC, a few ComM requesters and Dcm. Here it is, with all the names you will meet again.

Real ECUs have dozens of channels and users. This one is small enough to keep in your head and still has everything the course needs: two CAN networks, one Ethernet network, partial networking and diagnostics.

Three buses, four other ECUs

The example is a gateway (an ECU connected to several buses that passes data between them and keeps them awake together). It is connected to three networks:

  • body CAN, with the Door ECU and the Light ECU. It uses CanNm, and it uses partial networking (only some of the ECUs on the bus wake up, the others keep sleeping).
  • chassis CAN, with the Brake ECU. It also uses CanNm, without partial networking.
  • Ethernet, with the Head unit. It uses UdpNm.

On each of them, network management sends an NM PDU (the network management message each ECU sends cyclically while it needs the bus). On body CAN each ECU has a node identifier that it puts into its NM PDUs: the gateway 0x10, the Door ECU 0x21, the Light ECU 0x22.

One SWC, three ComM users

The application of the gateway is one SWC, BodyControl. It does not ask for "body CAN" directly. It owns three ComM user (a logical requester of communication in ComM, mapped to channels or PNCs) entries, one per function, and each user asks for communication on its own:

ComM userMapped toSo it wakes
UserComfortPNC Comfort (16)body CAN and Ethernet, but on them only the ECUs of Comfort
UserLightingPNC Lighting (17)body CAN, but on it only the ECUs of Lighting
UserChassischannel ChassisCanthe whole chassis CAN

ComM knows each network as a channel (one network the ECU is connected to, with its own number, the network handle): BodyCan = 0, ChassisCan = 1, Eth = 2. Lesson 5 shows how ComM combines the requests of several users on one channel.

Partial networking, lightly

A PNC (partial network cluster: a group of ECUs that are switched on and off together, independently of the other ECUs on the same bus) lets the gateway wake only the ECUs a function needs. The example has two:

PNC 16

Comfort

Door ECU and Head unit, with the gateway. It uses body CAN and Ethernet, so the gateway passes Comfort requests between the two.

PNC 17

Lighting

Door ECU and Light ECU, with the gateway. It uses body CAN only.

Each PNC is one bit in the PNC bit vector (bytes of the NM PDU with one bit per PNC; 1 means the sender requests that PNC). On body CAN the PNC bit vector is one byte long and starts at byte 2 of the NM PDU, right after the two bytes network management uses for itself; Ethernet uses the same offset. PNC 16 and PNC 17 are bits 0 and 1 of that byte. An ECU that belongs to neither requested PNC may keep sleeping even though NM PDUs run on its bus. The Brake ECU is not involved at all: chassis CAN has no PNCs. Part 8 explains how this works.

Dcm and the wakeup sources

Dcm answers a tester connected to the gateway. It is not a ComM user: while a diagnostic session is active on a channel, Dcm calls ComM_DCM_ActiveDiagnostic (Dcm tells ComM that diagnostics is active on this channel, which keeps it awake) for that channel; lesson 10 shows the details.

Three wakeup source (a configured source of wakeups known to EcuM) entries can wake the gateway:

Wakeup sourceWhat it is
ECUM_WKSOURCE_BODYCANThe CAN transceiver of body CAN detects bus activity
ECUM_WKSOURCE_POWERPower on
ECUM_WKSOURCE_DOOR_PINA pin of the gateway, wired to the door

A wakeup on body CAN is checked before the gateway acts on it: wakeup validation (checking that a wakeup was real, here that a valid CAN message follows, before the ECU acts on it) is switched on in CanIf for ECUM_WKSOURCE_BODYCAN. Lessons 34 and 35 show how.

Things to notice. The SWC never names a bus; it requests through its users, and the configuration decides which channels and PNCs that means. Two users can share a bus: UserComfort and UserLighting both end up on BodyCan. Dcm keeps a channel awake by its own interface, not as a user.
