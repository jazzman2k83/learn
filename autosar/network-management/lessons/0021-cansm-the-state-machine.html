Network and Mode Management in AUTOSAR Classic

Network Management

CanSM: one state machine per network

ComM asks for a communication mode; CanSM makes it happen on the hardware. For every CAN network it runs one state machine that switches controllers, transceiver and the sending of PDUs, step by step, and reports the reached mode back.

ComM talks to one bus state manager per channel; on a CAN network that is CanSM. CanSM itself does not touch the hardware: it calls CanIf, which passes the requests on to the Can driver and the CanTrcv.

What CanSM switches

in the microcontroller

CAN controller

The CAN controller (the CAN hardware unit in the microcontroller) is set to CAN_CS_STARTED, CAN_CS_STOPPED or CAN_CS_SLEEP. A network may have more than one; CanSM switches all of them.

between controller and wires

Transceiver

The transceiver is set to CANTRCV_TRCVMODE_NORMAL to communicate, or CANTRCV_TRCVMODE_STANDBY to sleep while still detecting a wakeup on the bus.

in CanIf

PDU mode

The PDU mode (whether CanIf lets PDUs through for a controller) is CANIF_ONLINE for full communication and CANIF_TX_OFFLINE for silent communication: receiving only.

CanSM stores one network mode per network, with the same three values ComM uses: COMM_NO_COMMUNICATION, COMM_SILENT_COMMUNICATION and COMM_FULL_COMMUNICATION. ComM requests one of them with CanSM_RequestComMode; all of CanSM's work then happens in its main function.

The main states

The state machine is called CANSM_BSM, and every configured CAN network has its own copy. Its states for the normal way up and down are:

StateNetwork modeHardware
CANSM_BSM_S_NOCOMCOMM_NO_COMMUNICATIONcontrollers asleep (or stopped), transceiver in standby
CANSM_BSM_S_PRE_FULLCOMon the way uptransceiver to normal, controllers stopped, then started
CANSM_BSM_S_FULLCOMCOMM_FULL_COMMUNICATIONcontrollers started, PDU mode CANIF_ONLINE
CANSM_BSM_S_SILENTCOMCOMM_SILENT_COMMUNICATIONcontrollers started, PDU mode CANIF_TX_OFFLINE
CANSM_BSM_S_PRE_NOCOMon the way downcontrollers stopped and put to sleep, transceiver to standby

The two pre-states are sub-state machines of their own. In each step CanSM calls CanIf, waits for the mode indication of the controller or transceiver, and only then takes the next step. If an indication does not come within a configured time, CanSM repeats the request and finally reports a runtime error.

The steps of the pre-states

Pre-stateSteps, in order
CANSM_BSM_S_PRE_FULLCOMtransceiver CANTRCV_TRCVMODE_NORMAL → controllers CAN_CS_STOPPED → controllers CAN_CS_STARTED
CANSM_BSM_S_PRE_NOCOM, transceiver without partial networking (ChassisCan)controllers CAN_CS_STOPPED → controllers CAN_CS_SLEEP → transceiver CANTRCV_TRCVMODE_NORMAL → transceiver CANTRCV_TRCVMODE_STANDBY
CANSM_BSM_S_PRE_NOCOM, transceiver with partial networking (BodyCan)clear the transceiver's wakeup flag → controllers stopped → transceiver normal → transceiver standby → controllers sleep → check the transceiver's wakeup flag

The path with partial networking takes care of wakeups that the transceiver may have seen during shutdown; lesson 43 explains why. The way up is the same for both.

Reporting back: to ComM and to BswM

When a state is reached, CanSM reports it twice. ComM gets the new communication mode through ComM_CanSM_ModeIndication and passes it on to its users and to BswM. BswM also gets CanSM's own state directly, so that its rules can react to it (lesson 27).

TransitionCanSM does, in this order
into CANSM_BSM_S_FULLCOMPDU mode CANIF_ONLINE; reports COMM_FULL_COMMUNICATION to ComM; reports CANSM_BSWM_FULL_COMMUNICATION to BswM
full to CANSM_BSM_S_SILENTCOMreports CANSM_BSWM_SILENT_COMMUNICATION to BswM; PDU mode CANIF_TX_OFFLINE; reports COMM_SILENT_COMMUNICATION to ComM
into CANSM_BSM_S_PRE_NOCOMreports CANSM_BSWM_NO_COMMUNICATION to BswM, then runs the steps
into CANSM_BSM_S_NOCOMstores the network mode; reports COMM_NO_COMMUNICATION to ComM if ComM had requested it

On the usual way down, ComM requests silent communication when network management enters Prepare Bus-Sleep Mode, and no communication when it reaches Bus-Sleep Mode. A channel without network management goes from full straight to no communication.

Up to R24-11 the mode indication is called ComM_BusSM_ModeIndication for every bus. R25-11's ComM specification names it ComM_<Bus>SM_ModeIndication, with CanSM as the prefix on CAN; the R25-11 CanSM specification still writes the old name. The states and steps of this lesson are the same in 4.4.0 and R20-11.

Try it

CanSM on the example ECU's network ChassisCan, below ComM. Each controller or transceiver step takes 0.1 s here; the log shows every call to CanIf and every indication back. Timings are small example values on a real-time clock.

Things to try: request the channel and follow CANSM_BSM_S_PRE_FULLCOM in the log; release it and wait for the way down through CANSM_BSM_S_SILENTCOM and CANSM_BSM_S_PRE_NOCOM; let the Brake ECU wake the bus and watch where the first PDU goes.

Things to notice. ComM only names a mode; CanSM turns it into an ordered series of controller and transceiver modes, each confirmed before the next. Full and silent communication differ only in CanIf's PDU mode: the controller runs in both. ComM learns the result from CanSM's mode indication, not from its own request.
