Network and Mode Management in AUTOSAR Classic

Network Management

PNC through COM signals

Up to R20-11, ComM did not talk to the bus NMs about PNCs at all. CanNm and UdpNm computed EIRA and ERA and handed them to COM like any received data; ComM read them as COM signals and sent its own PNC requests the same way.

Releases on this page: AUTOSAR 4.x up to R20-11. R21-11 adds the direct path through NmIf as a draft and marks the COM signal path obsolete; R22-11 removes the COM signal path. The rest of the course (lessons 40 to 46) describes the R25-11 path.

This lesson follows a PNC request in both directions through the old path, on body CAN of the example gateway, and then shows what R21-11 and R22-11 changed. The PNC state machine itself (lesson 41) is the same in both paths; only the way the bits travel differs.

Who computes what

CanNm, UdpNm

Compute EIRA and ERA

The bus NM filters each received NM PDU with the PNC filter mask, sets the bits of the requested PNCs, restarts their PNC reset timer and clears a bit when its timer runs out. The EIRA also takes the NM PDUs that this ECU sends. Whenever a bit changes, CanNm passes the new EIRA (one for all CAN channels) or ERA (one per channel) as a received PDU to PduR.

PduR, COM

Carry the bits

PduR routes the EIRA and ERA PDUs to COM. In COM each is an ordinary receive I-PDU with one signal: a bit vector with one bit per PNC. In the transmit direction COM holds the user data I-PDU of the NM PDU, in which the PNC bit vector lies.

ComM

Reads and writes signals

For each PNC a configuration names its COM signals in ComMPncComSignal (older ComM configuration, up to R20-11: a COM signal through which ComM reads EIRA or ERA, or sends its PNC requests), with a direction RX or TX and, for RX, a kind EIRA or ERA. ComM reads with Com_ReceiveSignal and writes with Com_SendSignal.

COM tells ComM about a change through ComM_COMCbk_<sn> (the ComM callback that COM calls when an EIRA or ERA signal was updated; <sn> is the signal's short name). The callback only notes the change; ComM reads the signal and runs the PNC state machine in its next main function.

The bit of a PNC follows the same rule in both paths: byte index = (PNC ID div 8) − PNC vector offset, bit index = PNC ID mod 8. On body CAN the PNC bit vector is one byte at offset 2, so Comfort (16) is bit 0 and Lighting (17) bit 1 of that byte, which is byte 2 of the NM PDU.

Try it

Step through a request in each direction on the body gateway. Receive: the Door ECU requests Comfort. Transmit: BodyControl requests Comfort through UserComfort. The signal names PncEira and PncTxBodyCan are examples; a project chooses its own.

The gateway case: ERA

A PNC gateway needs to know on which channel a request came from. With CanNmPnEraCalcEnabled on a channel, CanNm keeps an ERA for that channel, built only from received NM PDUs, and passes it through its own Rx PDU to COM. ComM reads it through a ComMPncComSignal with direction RX and kind ERA; ComMPncComSignalChannelRef names the channel, whose gateway type (active or passive) then decides on which channels ComM mirrors the request with Com_SendSignal. The rules of the gateway are the ones of lesson 44; only the transport is different.

What R21-11 and R22-11 changed

up to R20-11

Through COM

CanNm/UdpNm compute EIRA and ERA (CanNmPnEiraCalcEnabled, CanNmPnEraCalcEnabled, CanNmPnResetTime, CanNmPnInfo …) → PduR → COM → ComM_COMCbk_<sn>, Com_ReceiveSignal. ComM's requests: Com_SendSignal → COM → PduR → NM user data.

R22-11 and later

Through NmIf

NmIf computes EIRA and ERA from the PNC bit vectors that the bus NMs pass up, and calls ComM_Nm_UpdateEIRA and ComM_Nm_UpdateERA. ComM passes its IRA per channel with Nm_UpdateIRA. The parameters moved to NmIf (NmPnEiraCalcEnabled, NmPnResetTime …, lesson 54).

  • R21-11: the NmIf path appears as a draft (Nm_UpdateIRA, ComM_Nm_UpdateEIRA, ComM_Nm_UpdateERA), and the ComM change history says it "set the usage of ComSignals to obsolete": the requirements of the COM path and the container ComMPncComSignal are marked obsolete, as are the EIRA/ERA parameters of CanNm.
  • R22-11: the NmIf path becomes valid, and the obsolete requirements, ComMPncComSignal, ComM_COMCbk_<sn> and the CanNm EIRA/ERA parameters are removed.

What stays: the PNC state machine, the bit position rule, the filter mask idea, the reset timer and the gateway types. A project that moves forward keeps its PNC IDs and its NM PDU layout; it changes where the parameters live and drops the COM signals, the PduR routes and the COM I-PDUs of EIRA and ERA.

Between 4.4.0 and R20-11 the COM path itself is the same. R20-11 adds, as drafts, the synchronized PNC shutdown and PN learning with dynamic PNC-to-channel mapping, which still use the COM signals in that release (lessons 45 and 46). In 4.4.0 and R20-11 a PNC ID lies between 8 and 63; R25-11 allows up to 511.

Things to notice. In the old path the bus NM does the PNC work and COM is only the courier: ComM never calls an NM function for a PNC. Every bit change costs a trip through PduR and COM, and ComM learns of it only in its next main function. The R25-11 path removes the courier, not the logic.
