Network and Mode Management in AUTOSAR Classic

Network Management

CAN wakeup end to end

The Door ECU starts talking on body CAN while the gateway sleeps. Its CanTrcv notices, EcuM checks that the wakeup was real, and ComM starts the channel and NM.

Lesson 34 showed wakeup validation as EcuM sees it. Here every module of the CAN path takes part: the transceiver and CAN drivers, CanIf, CanSM, EcuM with its callouts, ComM and NM. The example is ECUM_WKSOURCE_BODYCAN of the gateway, which names channel BodyCan.

Detecting the wakeup

Before the sleep, CanSM put the CAN controller of body CAN to sleep and the transceiver to standby, and EcuM armed the transceiver as a wakeup source. Only in such a mode can the hardware report a wakeup. When another ECU sends on the bus, the transceiver signals it, by an interrupt or by polling.

The integration code then calls EcuM_CheckWakeup (EcuM's function for checking wakeup sources, called for example from the wakeup interrupt), which passes the source to its integrator hook. The hook calls CanIf_CheckWakeup (CanIf asks the CAN controllers and transceivers configured for this wakeup source whether they woke up). CanIf asks the transceiver driver with CanTrcv_CheckWakeup (the transceiver driver checks its hardware and reports a wakeup to EcuM), and the driver reports EcuM_SetWakeupEvent. The source is now pending.

Validating it on the bus

After the WakeupRestart sequence EcuM's main function starts the validation. The callout EcuM_StartWakeupSources calls CanSM_StartWakeupSource (CanSM switches the transceiver to normal and starts the CAN controllers of the network, for validation only). CanSM enters its side state CANSM_BSM_WUVALIDATION (the CanSM state in which transceiver and controller run for wakeup validation, without full communication): transceiver to normal, controller stopped, then started.

The controller now receives frames. Stopping it has also changed CanIf's PDU mode: CanIf sets a stopped controller to receive only (CANIF_TX_OFFLINE), so received frames go up to the upper modules while nothing is sent. For the validation CanIf also remembers the first valid CanIf_RxIndication (the call with which the CAN driver hands a received frame to CanIf) on that controller. If validation by NM is configured, only NM PDUs count; otherwise any received frame of a configured Rx PDU does.

An NM PDU received now reaches CanNm, which is still in Bus-Sleep Mode. CanNm reports it with Nm_NetworkStartIndication, and NmIf passes it on as ComM_Nm_NetworkStartIndication. ComM switches to full communication on this indication only while communication allowed is set. In the example BswM withdrew it before the sleep and sets it again only after the validation (lesson 49), so the indication has no effect here; the channel starts through the validated wakeup.

In each main function cycle the callout EcuM_CheckValidation calls CanIf_CheckValidation (CanIf confirms the wakeup to EcuM if it has stored a received frame since the wakeup). Once a frame is stored, CanIf calls EcuM_ValidateWakeupEvent. If the validation timeout runs out first, the callout EcuM_StopWakeupSources calls CanSM_StopWakeupSource (CanSM switches the network back to no communication after a failed validation), and the gateway sleeps again. CanIf clears the stored frame when the controller goes to sleep.

After the validation

EcuM tells ComM with ComM_EcuM_WakeUpIndication and BswM with ECUM_WKSTATUS_VALIDATED. ComM moves channel BodyCan to COMM_NO_COM_REQUEST_PENDING; as soon as BswM has set communication allowed, it enters full communication. It asks CanSM for full communication, which leaves the validation state and sets the PDU mode online, and it starts NM with Nm_PassiveStartUp. CanNm enters the Repeat Message State. Lesson 36 shows how this passive start differs from an active one.

The validation path (CanIf storing the first received frame, EcuM_CheckValidation, CanIf_CheckValidation, EcuM_ValidateWakeupEvent) is the same in 4.4.0 and R20-11. In those releases EcuM_CheckWakeup is itself the integrator callout (from R21-11 EcuM calls EcuM_CheckWakeupHook), and a transceiver driver that checks its wakeup asynchronously and finds none reports it with EcuM_EndCheckWakeup, which R21-11 removed.

Things to notice. The wakeup is reported from an interrupt, but validated in EcuM's main function. During validation the controller runs and receives; received frames go up, and CanIf also notes that something valid arrived. An NM PDU only makes CanNm report a network start, which ComM ignores while communication is not allowed. NM is started by ComM after the validation, not by the received frame.
