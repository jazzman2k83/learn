ComM

TopicIn shortLesson
ComM users and channelsUsers request COMM_FULL_COMMUNICATION or COMM_NO_COMMUNICATION; each is mapped to channels or PNCs; the highest request per channel wins.5
The channel state machineThree communication modes as main states; sub-states such as COMM_FULL_COM_NETWORK_REQUESTED and COMM_FULL_COM_READY_SLEEP.6
Network requested and ready sleepComM only decides whether this ECU still needs the bus; when the bus sleeps is decided with the other ECUs, by NM.7
NM variantsFULL, PASSIVE, LIGHT, NONE, SLAVE_ACTIVE, SLAVE_PASSIVE: how a channel goes to sleep after the last release.8
Communication allowedBswM must allow communication on a channel before ComM switches it on; then BswM starts its I-PDU groups.9
Dcm keeps the channel awakeComM_DCM_ActiveDiagnostic holds the channel during a diagnostic session; Dcm is not a ComM user.10
Communication inhibitionWake up inhibition and limit to COMM_NO_COMMUNICATION override the users' requests.11

Network management

TopicIn shortLesson
The coordination algorithmA node that needs the bus keeps sending NM PDUs; when nobody sends any more, all nodes sleep.12

The NM timersMessage Cycle Time, Repeat Message Time, NM-Timeout Time, Wait Bus-Sleep Time; see the NM timers sheet.14

Passive mode, communication control, bus load reductionA node that never sends; sending stopped on request of a tester; many nodes that send less.17

Wakeup

TopicIn shortLesson
Wakeup sourcesOne bit each; states none, pending, validated, expired; reported to BswM.33
Wakeup validationEcuM switches the source on and asks until the wakeup is confirmed or the validation timeout runs out.34

NM coordinator

TopicIn shortLesson
NM coordinatorA gateway keeps all buses of its NM coordination cluster awake while any one is needed.37
Coordinated shutdownShutdown timers hold each bus a little longer, so that all reach Bus-Sleep Mode at the same moment.38
Nested sub-busesA gateway below waits for the NM Coordinator Sleep Ready Bit; a started shutdown can be aborted.39

Partial networking

TopicIn shortLesson
Partial networkingECUs grouped by function in PNCs; only the PNCs somebody needs stay awake.40
PNC state machineOne per PNC in ComM: requested here, needed only by others, about to go, off.41
EIRA and ERANmIf filters the received PNC bits into the EIRA and the ERA; a bit drops after the PNC reset time.42
Selective wakeupThe CAN transceiver wakes the ECU only for a wakeup frame that requests one of its PNCs.43
PNC gatewayTurns a PNC request received on one bus into its own request on the other buses.44
Synchronized PNC shutdownThe top of a gateway hierarchy announces the end of a PNC, so that all ECUs leave it together.45
PN learningThe gateway asks the ECUs which PNCs they belong to and extends its PNC-to-channel mapping at run time.46

The flows end to end

FlowIn shortLesson
Power on to full communicationReset, EcuM startup, BswM allows communication, UserComfort's request down to the first NM PDU.47
Woken by another ECUThe Door ECU requests PNC Comfort; the gateway wakes, validates, starts body CAN passively.48
Going to sleepThe last user releases; NmIf passes the release on and each bus goes down on its own (no NM coordinator next to partial networking); BswM sends the ECU to sleep.49
A PNC request across the gatewayA request for Comfort ends up in the PNC bit vector on body CAN, on Ethernet, or both.50
