Network and Mode Management in AUTOSAR Classic

Network Management

The older and the newer way

Two parts of the course worked differently in older releases: EcuM Fixed decided shutdown by itself, and PNC requests travelled between ComM and the bus NMs as COM signals. In both cases the newer way moves the work to another module. This sheet puts the two ways side by side and maps each older concept to its newer equivalent.

EcuM Fixed and EcuM Flex with BswM

EcuM Fixed has its own specification up to 4.3.1, which marks it obsolete; 4.4.0 removes it. In 4.3.1 both variants are specified, so a project of that release may use either. R25-11 has only EcuM Flex.

EcuM Fixed · 4.3.1 and older

EcuM decides

The states are fixed by the standard. EcuM stays in RUN while a RUN request is placed, a ComM channel is not idle (ComM_GetState) or EcuMRunMinimumDuration is not over; after the last POST_RUN request it shuts down. It calls ComM_CommunicationAllowed itself. ComM is a resource manager: a channel out of no communication keeps the ECU running.

EcuM Flex + BswM · R25-11

BswM decides, EcuM executes

EcuM keeps the STARTUP phase, the SHUTDOWN phase, the SLEEP phase and the wakeup handling. It only reports the RUN requests with BswM_EcuM_RequestedState. BswM rules combine them with the ComM modes and whatever else matters; an action list allows communication, selects the shutdown target and calls EcuM_GoDownHaltPoll. Without such a rule, nothing shuts the ECU down.

PNC through COM signals and PNC through NmIf

The PNC state machine is the same in both ways; what changed is how the PNC bits travel between ComM and the bus NMs, and which module computes EIRA and ERA.

4.x to R20-11

COM signals only

The bus NMs compute EIRA and ERA; ComM reads and writes COM signals.

R21-11

Both, in transition

The path through NmIf appears as a draft; the COM signal path and its parameters are marked obsolete.

R22-11 and later

NmIf only

The NmIf path is valid; the COM signal path, ComMPncComSignal and the bus NM parameters for EIRA and ERA are removed.

Through COM signals · up to R20-11

The bus NM computes, COM carries

CanNm and UdpNm apply the PNC filter mask, run the PNC reset timers and pass a changed EIRA or ERA as a received PDU through PduR to COM. COM calls ComM_COMCbk_<sn>; ComM reads the signal with Com_ReceiveSignal in its next main function. ComM writes its own requests with Com_SendSignal into the NM user data.

Through NmIf · R22-11 and later

NmIf computes and calls ComM

The bus NMs pass every received PNC bit vector to NmIf with Nm_PncBitVectorRxIndication. NmIf filters, keeps EIRA and ERA with their timers, and calls ComM_Nm_UpdateEIRA and ComM_Nm_UpdateERA. ComM passes its IRA per channel with Nm_UpdateIRA; a bus NM that sends an NM PDU fetches those bits with Nm_PncBitVectorTxIndication.

Things to notice. Both changes move a decision out of a module that did it implicitly. EcuM Fixed obeyed the RUN requests by itself; EcuM Flex only passes them on, and BswM decides by configured rules. The bus NMs computed the PNC arrays and COM carried them; NmIf now computes them for all buses and calls ComM directly. In both cases the values a project chose (RUN users, PNC IDs, bit vector layout, mask bytes) survive; their place in the configuration changes.
